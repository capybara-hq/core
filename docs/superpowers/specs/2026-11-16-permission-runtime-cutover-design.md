## Required managed-output interface and wire

Use the merged SDK method unchanged:

```ts
readOutput(h: SandboxHandle, ref: SandboxExecutionRef,
  opts: {offset: number; maxBytes: number; signal: AbortSignal}): Promise<
  {data: Uint8Array; offset: number; nextOffset: number; totalBytes: number}
  | {unavailable: "lost" | "expired"}
>;
```

Add device operation `backgroundReadOutput` with request args exactly `{ref, offset, maxBytes}`. No scope, path, actor override, grant or limits is accepted. Ref has exactly `instanceId`, `instanceGeneration`, `operationId`, `executionId`; it must match the task's stored device/provider/instance. Success wire value is exactly `{dataB64, offset, nextOffset, totalBytes}`; unavailable is exactly `{unavailable:"lost"|"expired"}`. Unknown keys reject. Bounds: offset/nonnegative safe integer; maxBytes/integer 0–65,536; totalBytes/nonnegative safe integer; nextOffset equals offset plus decoded byte length, with no overflow. For offset beyond total, require empty data and unchanged nextOffset. For an available range, decoded length equals min(request budget, total-offset); unexplained short ranges reject. Decode only canonical valid base64 under frame size limits. Response offset must equal this request's offset.

The kernel adapter sends `min(callerBudget,65536,maxReadBytes(effectiveFrameBytes))`; response invariants use that sent budget. The effective capacity and multi-read algorithms below are normative; a single clamped overlap/suffix request is insufficient. Metadata probes always use zero. If a nonzero read cannot fit data, fail as a transport-capacity error rather than claim EOF. Server validation and SDK cap remain backstops. Deadline/abort is OP_DEADLINE_MS with the caller signal; it cancels only the read. A relay RPC ID may change on retry; the execution ref and byte coordinate do not. Wrong ownership/generation raises scope-denied, absent/untrustworthy retained storage returns lost, known expiry returns expired. Unknown start state is not silently remapped to no launch.

Backend output is one raw merged byte stream before capture, with append-only committed snapshots. Preserve accepted spool journal predecessor/decision evidence, sticky faults and independent stopped evidence. A collector fault remains lost even if child exit raced; cancellation may separately become stopped. Retained bytes may remain readable through lost supervision; do not discard them merely because status is lost. Never adopt an artifact/path/PID as a replacement reference. Output capture truncation is not spool truncation or task cancellation.

## Consumer mapping and authority

| Consumer | Authorization and byte behavior |
| --- | --- |
| TaskOutput | Task's own conversation and org only, fresh device-owner access, existing invocation access. Assemble the parser history from `max(0,readOffset-4096)` and a fresh-byte window through successive bounded reads; see the progress algorithm below. Advance PG readOffset only for newly delivered bytes, including terminal replacement decoding at the verified stream end. Remaining count is max(snapshotTotal-deliveredOffset,0). Repeat bounded calls for larger tool budget; no string-dedup heuristic. |
| HTTP output | Existing visible task conversation or permitted ancestor path and fresh user/device checks. Probe N with budget 0, then assemble every byte of `[max(0,N-tailBytes),N)` through successive capacity-bounded reads. Growth after probe does not extend this response. Preserve leading-fragment UTF-8 handling, unavailable reason and finished-event fallback. |
| TaskStop / finish / poll summary | Existing own-conversation or authorized human stop path. Exact-ref status/stop/tail only; five-second grace, final 20 lines, finish event cap 4,000 characters. Never read a file with exec after stop. |
| Ordinary Read artifact | Current ordinary file authorization only. No task capability grants a path, no profile widening and no automatic resume from task API. Artifact absence/replacement does not alter retained spool bytes. |

TaskOutput control API never accepts a caller-supplied ref: load it from the authorized row. HTTP must not let an ancestor visibility check turn into arbitrary device/ref authority. Use exact recorded generation even if the device has since recreated; do not send old ref to a new instance and search its files. Read access requires no fresh execution operation, profile approval, owner grant or provisioning. Existing real device-access revocation still denies reads.

Kernel state retains task ID, device/provider/incarnation, full execution ref, starting scope and authority provenance, operation/input hash, retention deadline, cancellation intent/outcome and byte cursor. Ref publication and start uncertainty are distinct. A successful start retry returns the original ref/authority; it neither truncates files nor reruns the command. Tail cannot implement positional output. Output retention cleanup cannot prune active cancellation, retirement or at-most-once records.

## B4 — generation allocation, binding handshake and manifest producer

Keep the accepted identity comparison `instanceGeneration === String(device_instances.created_at.getTime())`; do not substitute a device UUID or first-operation ref. Use a two-stage **post-commit binding** for local instances:

1. A first authenticated v3 hello may be unbound: `instanceGeneration:null`, no runtimeIdentity, and permissionSupport reports no supported operations with an initialization reason. The kernel treats this as unprobed/no installed report, not as a verified unsupported capability result that would wrongly prohibit the accepted deferred-check consent flow. Extend the canonical v3 hello schema for this explicit state, rather than inventing an empty/fake generation. A reconnect with a persisted binding sends its exact bound generation and verified identity instead.
2. Existing local create reports roots under current independent limits but does not create a usable operation supervisor or choose a generation. Allocate an exact integer epoch-millisecond value through a durable per-device high-water record under the same device authority/row fence: `max(database now in ms, highWaterMs + 1)`. Commit both highWaterMs and created_at representing that exact millisecond in the same transaction. The high-water record lives independently of device_instances and survives instance deletion/reset/rebuild; never reconstruct it from only the current row. Initialize once from the validated greatest existing instance/binding/retirement generation; inconsistent prior identity blocks conversion. Refuse timestamp/date-range exhaustion rather than wrap. Thus clock rollback, same-millisecond replacements and deletion/recreation cannot reuse a prior generation; concurrent attempts serialize/CAS. A device identity is never recycled after deletion. Preserve 6c instance publication/consent-reset semantics. Commit a random bindingId in a new instance binding record with status `awaiting-device`; permission report remains unprobed.
3. Before downgrade to shared/admission, the local lifecycle coordinator sends authenticated private RPC `bindInstance` with exactly `{instanceId,instanceGeneration,bindingId,expectedPreviousGeneration}`. instanceId is the device handle ID; generation and bindingId are the committed row values; previous is the last acknowledged binding or null. This is a local-provider lifecycle method/coordinator, not a user SandboxOperation or a new optional provider fallback. Wire parser validates bounded identifiers and refuses caller-provided paths/policies/manifests. Reconnect reconciliation retries the identical binding ID; no ordinary operation can bind implicitly.
4. The device verifies its authenticated device ID, stored previous binding and exact trusted roots, strict owner policy, installed manifest and retirement state. It durably writes the bound identity before constructing/enabling that generation's supervisor. Same binding/generation retry is idempotent; the durable device binding records both, and an equal generation with a different bindingId is a conflict, never permission to reopen/adopt another journal. A different binding/generation is refused while live foreground work or unknown retirement obligations of an older generation remain; only after the bind has passed every other check are the older generation's live background tasks exact-stopped (bounded; a stop that does not settle stays owned as cancel-pending and refuses the bind), so a refused bind stops nothing. A `create` exact-stops the bound generation's live background tasks the same way. The kernel's durable legacy gate is also checked before sending bind. A new timestamp cannot clear either side's old uncertainty. Failure after persistence is recovered by the same request, never a new generation to escape a conflict.
5. bindInstance returns `{instanceId,instanceGeneration,bindingId,runtimeIdentity,permissionSupport,ownerCeiling}`. The active authenticated connection provides machine identity. The kernel re-enters the existing device authority writer, verifies instance row/generation/provider/bindingId and machine/connection fencing, calls PermissionRuntimeReports.record and the common owner-summary publisher, then marks the binding installed. Only a matching installed binding plus current publication admits scoped work. Failed validation leaves unprobed/blocked. A delayed old reply cannot populate a replacement row.

No distributed lease is acquired inside these DB transactions. Provider/RPC I/O occurs outside them while the lifecycle lease remains held; commits validate that lease's fence. If a replica dies or commit acknowledgment is lost after committing awaiting-device, another holder reads/reconciles that exact committed generation/binding, never allocates a replacement solely to retry. Required collision tests force equal database millisecond values, clock rollback, instance-row removal, concurrent allocation and lost-commit reply; prior refs/journals remain distinct and old retirement obligations survive. A bound hello can finish installation only against the matching pending/installed row and bindingId under those same checks; it cannot create an instance row. If no provider/runtime evidence is available, preserve unavailable state rather than report success.

**Lifetime distinctions.** Socket reconnect keeps the same process supervisor/generation/binding and re-reports current verified bytes. Process supervisor restart keeps the persisted binding only for accepted same-generation journal/spool recovery: it never reattaches processes by PID or claims surviving lost work complete. Live/uncertain prior ownership blocks new operation admission until exact cancellation/retirement is established; retained output/control remains available under accepted recovery rules. A real instance replacement is allocated by the kernel only after lifecycle/retirement evidence and gets a new timestamp/binding; old refs reject. Service restart, credential reload, helper update or arbitrary device assertion is not proof of physical retirement. A changed installed artifact/environment invalidates the old report and requires revalidation and the applicable admission authority transition; it cannot silently relabel running old workers with new identity. Their original identity and obligations remain recorded until settled. Linux same-pinned-root proof remains PLATFORM HELD regardless of handshake validity.

**Canonical manifest (version 1).** The production package build emits a private manifest beside the device executable; add `packages/device/tools/runtime-manifest.ts` as its generator and `packages/device/src/exec/runtime-manifest.ts` as runtime verifier. Use the accepted stagePrivateSource hash/owner checks for staged bytes and verify their returned identity before use.

Each entry is the tuple `[logicalName,byteLength,sha256]`, with UTF-8 bytes, byteLength a nonnegative safe integer, lowercase 64-hex SHA-256, unique slash-separated package-relative logicalName with no parent segments. ## B5 — effective frame capacity and bounded output assembly

Extend hello with `transport:{maxFrameBytes:number}` from the device's actual saved/configured send-and-receive limit (currently credential.maxFrameBytes). The authenticated kernel gateway replies before requests with `ready:{connectionId,maxFrameBytes}`, where the effective value is min(device advertisement, current deployment gateway limit). Both values must be safe positive integers and fit the control-frame minimum; if hello/ready themselves cannot fit, refuse connection with an actionable configuration error. Store effective cap and connectionId with the active machine/gateway-holder record. The provider/relay obtains that exact connection's cap from DeviceTargets, not just current global config. Requests include/fence the relay connection identity internally so an old capacity cannot be used on a replacement socket. Device fit(), incoming parser and kernel outgoing/incoming frame checks all enforce the effective cap. No data requests precede ready.

A saved client limit lower than deployment yields the lower limit; a newer lower deployment limit also wins. A runtime cap decrease closes/quiesces the old transport before requests use the new value and requires the same handshake; there is no silent stale-cap optimism. Reconnect may change capacity while keeping task refs. An in-flight read encountering reconnect/capacity mismatch fails and may retry from the same byte offset after negotiation; no cursor advances for bytes not delivered. Provider semantic read bounds stay 65,536 decoded bytes regardless of framing.

Define `C=min(65536,maxReadBytes(effectiveFrameBytes))` using the existing conservative 65,536 envelope reservation. Metadata probes use maxBytes=0. If C=0 and unread data is needed, return an actionable transport-capacity error immediately; do not loop or report EOF. C>0 works even when C<=4096 by reading multiple adjacent ranges. Deadline/cancellation bounds the loop; there are no fixed sleeps or unbounded transport retries.

**TaskOutput assembly:** snapshot stored cursor R, get committed total N via zero-budget read, set H=max(0,R-4096). Assemble history `[H,min(R,N))` by consecutive reads at the *next unassembled offset*, each budget min(C,end-position); never repeatedly read H. A successful range may report a larger total, but slice/budget remains bounded to the captured endpoint. Require totals not regress below N for the same retained snapshot; otherwise return lost/error, not false EOF. If R>N, treat the cursor/storage mismatch as unavailable rather than moving it backward. A valid empty stream at R=N returns no new output normally.

Then assemble fresh `[R,F)` where F=min(N,R+freshBudget), freshBudget is the existing tool-output budget capped per assembly to at most 61,440 bytes and at least 4 bytes when data is available; transport chunks can be 1 byte. Keep at most 4,096 history bytes plus this fresh window (65,536 bytes total) and a bounded decoder carry, never the retained full spool. If a larger existing tool budget is used, process sequential such windows through the existing bounded result/spill path; the total result budget remains enforced. Parser receives the exact history plus newly delivered bytes, so split login codes are preserved. Chunk size never defines byte ownership.

For a live stream or a window ending before the final committed end, deliver only the whole UTF-8 prefix; retain an incomplete trailing sequence by not advancing over its bytes. Fetch adjacent raw bytes up to the window/end to complete a character even when C<4. If the live committed end itself holds an incomplete sequence, return a truthful no-new-complete-text result and wait for a later caller/poll; do not spin against an unchanged N. When status establishes terminal collection before the metadata snapshot (or a subsequent terminal metadata check confirms the same final N) and F=N, consume all remaining raw bytes and decode invalid/incomplete sequences using the existing UTF-8 replacement behavior; advance by raw byte count, never replacement-character encoded length. This terminal rule also works when the window happens to equal its budget. If terminal status arrives after a running snapshot, re-probe metadata or treat that window as non-final; do not assume the earlier N was final. A task already terminal in the kernel (including lost) may decode the last retained snapshot as a terminal display boundary using replacement bytes, as the existing ended branch did, without claiming collector completion or process success. This display rule consumes only actually returned retained bytes; it never synthesizes unavailable bytes or alters the lost outcome. Stop/lost/output-fault wording remains independent.

Advance PG cursor monotonically from R to R+deliveredRawBytes only for text included in the returned tool result, preserving existing concurrent-read semantics. If deadline expires before any fresh text is assembled, return timeout/capacity failure without cursor progress, not a repeat-read loop. If a bounded partial fresh prefix is returned, advance only for it. Remaining count uses max(N-deliveredOffset,0), not a later response's grown total. Concurrent appends appear next read; duplicate/retried raw reads do not consume bytes provider-side.

**HTTP suffix:** choose requested tail budget B<=65,536, probe N, set S=max(0,N-B). Read `[S,N)` using adjacent chunks budget min(C,N-position), assembling at most B bytes. After complete assembly remove only the leading partial UTF-8 fragment per existing HTTP behavior; never apply terminal 20-line limits. The response's captured endpoint remains N even if every later range reports a larger total. If interruption/storage failure prevents completion, use the existing explicitly unavailable/event-summary path rather than return a beginning fragment falsely labeled the suffix. N=0 needs no data read; C=0 with N>S is a deterministic capacity error. This preserves exact range semantics without changing the accepted provider API.

Required cases include C=3072 from frame 69,632, C below/equal/above 4096, C=1/2/3 at four-byte UTF-8 boundaries, terminal invalid/incomplete bytes, zero capacity, saved client/config mismatch, reconnect mid-range and concurrent growth after metadata. Assert bounded memory, adjacent request offsets, no overlap-only loop, cursor/remaining byte correctness and HTTP suffix endpoint N.
