## What I verified

- **Replay never touches live state.** Eval modules import no sandbox/permission/approval/device service. The feeder writes only `permission_context` events into the generated conversation, fails closed on a foreign conversation/run, writes nothing once aborted, and is created before seeding. `RecordedToolPipeline` copies recorded results; unmatched results get `REPLAY_NO_RECORDING` without a review. Integration test: no spied entrypoint called, no fake sandbox op, tool counter unchanged, no `permission_reviewed` / `approval_requested` invented, DB profile changed to full-access after the snapshot without effect.
- **B4 mapping (`selectOriginalRequest`, `permissionFeedPlan`).** Exact attempt; interior gap → greatest earlier same-step attempt; before the first recorded attempt → first attempt (original attempt 2 feeds generated attempt 1); past last → last; missing step → last request of greatest earlier step, never a later one; before every step / no requests → none; past every step → final request. Requests in callSeq order, `U = min(toSeq, callSeq-1)`, attempt fallback 1, duplicates/backward step, attempt or U rejected as `eval.snapshot_invalid`. `toSeq` is `last.seq` of the built events (`build.ts:1026`) and `model_call` idem is `model_call:<run>:<step>:<attempt>` from a single writer (`model-call.ts:1863`), so valid logs never trip the rejections. Monotone `reached`, `firstVisible <= reached` is equivalent to "seq ≤ monotone U" given the U monotonicity check. Contexts never seen by an original request are never fed. Only `seq > R` and target `runId`; seeds (`seq < R`) are never reappended. A/B before one call fed in source order in one batch.
- **Reentry/idempotency.** `EventLog.append` returns the existing event on an idem hit, per input (`event-log.ts:461-490`); a fresh feeder over the same log writes nothing new (unit test with a fake log that mirrors this). Key `replay_permission_context:<generatedRunId>:<originalSeq>` as specified.
- **Candidate compaction not compared to original.** `recordedRunPermissionDrift` uses only snapshot events and original `model_call`s of the target run; generated seqs/hashes are never compared (by construction). Earlier-run tampered metadata alone does not count; target-run tampering and deletion do.
- **Old recordings.** Unmarked recordings get `undefined` (no feeder key in loop deps: `"permissionContext" in out === false`), no drift, no `review` key, no marked paths. All 7 historical fixture files still match the 9.2 sha256 list (unit test reads the list); `git diff 239351676 -- packages/kernel/test/evals/fixtures` is empty. Integration: an old recording yields no permission events and no `permissionContext` metadata on generated calls. Reconstruct and rename-compat zero-drift groups pass.
- **Review copying.** Validated with the exported strict `ReviewRecordSchema` (history: only additive optional fields since `ac4d20578`, so older stored reviews still parse), copied with `structuredClone` of the original (not `parsed.data`), so key order and fields stay exact; absent stays absent; only matched results carry it; a deny stays a deny with the recorded content/isError.
