# Background sub-agents, `SendMessage` and the agent map — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sub-agents run in the background, nest up to 3 levels below the root, talk to their parent
and children with `SendMessage` / `SubagentHandback`, wake idle parents, and are shown in an agent
map dialog (tree, live summary, read-only transcript).

**Architecture:** The `Agent` call gets its `tool_result` at dispatch; everything a child later says
reaches its parent as one new absorbable, model-visible event `subagent_delivery`, woken by the same
`ensureRun` / wake-rules path that `background_task_finished` uses. Parent → child messages are
`user_message`s in the child log, absorbed by the child's running loop or starting a child run. The
web gets one tree API and three design components rendered in one dialog.

**Tech Stack:** NestJS + Fastify kernel, Kysely / PG, BullMQ, vitest; Next + TanStack Query web;
`@capybara-hq/design` React components; Playwright visual tests.

**Spec:** `docs/superpowers/specs/2026-11-06-agent-map-design.md` (amends
`2026-10-26-subagents-design.md`; reuses `2026-11-05-background-bash-design.md` §3). Mockups:
`docs/superpowers/specs/2026-11-06-agent-map/`.

## Global Constraints

- Pre-0.1.0: no compatibility layers or legacy shims; applied migrations are immutable; new
  migrations start at `0074_` (`0073_org_extension_point_defaults.sql` is the highest).
- Model-facing text (tool descriptions, refusals, rendered events, preamble) is English and passes
  the tool design check; UI text goes through i18n (zh and en); zh copy writes agent as 智能体
  (子智能体, 智能体图); no "主 agent" / "第 N 层" labels.
- `subagents.maxDepth` counts levels below the root: default `3`, bound `1–5`, `1` = no nesting.
- Concurrency default stays `4` active children per parent conversation.
- Multi-replica rules of AGENTS.md: no in-process state or timers; enqueues, bus publishes and Redis
  calls in `afterCommit`; BullMQ queue names and job ids contain no `:`; idem keys deterministic.
- Kernel conventions (`pnpm check:kernel-conventions`): `@Injectable` providers with explicit
  `@Inject`, `@Transactional` + `KernelDb`, DTOs with `createZodDto` + `@ZBody/@ZQuery/@ZParam`.
- Web rules (`pnpm check:web-ui`): page = template + design components, no styles in `apps/web`,
  reads through `defineQuery`, keys from `lib/query/keys.ts`, writes through `useAppMutation`.
- Replay: everything model-visible is in a log; replays never dispatch, send, hand back or wake; run
  `test/evals/reconstruct.test.ts` and `test/tools/rename-compat.test.ts` before Task A2 and after
  every kernel task.
- Changesets: `@capybara-hq/kernel` (behaviour); `@capybara-hq/capybara` + `@capybara-hq/web`
  (fixed group) for the UI.

## Decisions this plan makes (spec §11, left to the builder)

- **Event names:** `subagent_delivery` (new, model-visible, absorbable); `run_started.trigger` gains
  `"subagent"`; `user_message.dispatch` gains `kind: "task" | "message"` (absent = `"task"`).
- **Fork skills keep the `subagents` wait** (spec §5.4): `context: fork` dispatches stay foreground
  through `advanceSkillForks`; `timed_out`, `Waits.expire` for subagents, `sweepOverdueSubagents`
  and the resume condition's third `NOT EXISTS` stay, but only fork dispatches
  (`subagent_dispatches.for_skill = true`) are counted by them.
- **Budget window (spec §6):** a person-triggered root run (`trigger` absent or `"message"`) opens a
  window; every other run of the tree (children, wake runs) carries `runs.budget_run_id` = that run.
  Tokens (`runs.subagent_tokens_used`) and dispatch counts are read on the budget run.
- **Children wake** on parent messages and on their own background Bash finishes; the checks run
  against the root conversation (queue paused, trigger account can send); one config switch,
  `runtime.wakeOnBackgroundTask`, renamed nowhere (it already means "wake on background events").
- **Entry points:** a "智能体图 / Agent map" action in the `SubagentGroup` header and a title-bar
  panel icon shown while the conversation has sub-agents; the dialog state lives in the URL hash
  (`#agents`, `#agents=<id>`, `#agents=<id>/transcript`). The sub-agent right panel stays for now.

## Review Focus

1. A child finishes while its parent run is mid-step: the delivery is absorbed exactly once at the
   next model call and no wake run starts (Task A5 test `delivery during a parent run is absorbed,
   not woken`).
2. `SendMessage` to a child whose run ends between the check and the append: a new child run
   starts and the message is in it, never lost (Task A6 test `message racing a child finish starts a
   run`).
3. A depth-3 agent's approval shows in the root conversation and resolving it there resumes the
   depth-3 run (Task A8 test `great-grandchild approval surfaces in the root`).
4. The root's stop leaves children running; deleting the root stops the whole tree (Task A7 tests).
5. Logs written before this change (foreground `Agent` with `resume`, `subagents` waits) still
   rebuild with zero drift (Task A10 test `foreground-era log replays with zero drift`).
