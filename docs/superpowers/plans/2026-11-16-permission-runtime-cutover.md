## Phase 8.2 — durable launch identity and genuinely authorized artifacts

Files: `background/{launch,store,background.schemas}.ts`, Bash background branch, operation admission/facade integration, new plain-SQL migration and `db/kernel-schema.ts`. Consume accepted Task 7 issuance and 6b/6c fences; do not reimplement them.

Use the handoff's retained-intent `background-running` state and shared `isExecutionMethod` classification; ordinary foreground complete must not retire background authority at start acknowledgment. Persist the task reservation, launch intent, operation ID, per-method input digest, invocation/run claim, task-owned tag, exact instance/generation, starting scope/profile revision, permission grant locator, authenticated network authority and retention deadline before dispatch. Store an exact `SandboxExecutionRef` only from the typed start result. Distinguish pending/pre-effect, dispatched or consumed-unknown, acknowledged, cancel-pending and terminal evidence; a null ref is not proof of no launch. Crash recovery retries the same identity/hash; it never relaunches using a new ID. Conditional PG transitions and transactional outbox carry cancel intent and completion. No distributed lifecycle lease/LockService lock is acquired inside a transaction. Required authority XactLocks are acquired inside their transaction in the accepted order.

Artifact decision: new tasks use `${workingRoot}/.capybara/tasks/${taskId}.out`, where workingRoot is the selected project's trusted root (or the default workspace when no project exists), and the exact path must already be covered by the admitted starting write roots and implicit-write protections. A Full operation uses the same deterministic placement. This is a new-task location change, not a migration of old paths. Persist the absolute path before launch and include it in the stable start input hash. The accepted spool helper creates/pins parents and an exclusive regular artifact under that authority; any collision, symlink, read-only root or denial fails before launching. No fallback to roots.tmp/default workspace, no added root/grant, no preparation-purpose abuse. Keep the authoritative private spool separate and unreadable through user operation scope.

Do not advertise outputPath as created until artifact setup and start acknowledgment succeed. Retain artifact paths as ordinary file references after terminal output expiry; current Read authority still applies independently. A profile narrowing can deny ordinary Read while an authorized task API read remains valid. Missing artifact after user edits never substitutes for private spool authority.

Proposed gates: lost start acknowledgment produces one launch and stable files/ref; same operation with changed input rejects; pre-ack owner narrowing, stale invocation and cancellation races; reservation cap; max task duration; selected project outside workspace with workspace/tmp absent from write roots; denied or swapped artifact parents produce zero launches and no widening. Review this phase alone as a trust-boundary/persistence change.

## Phase 8.3 — task consumers, cursor and exact completion

Files: `background/{session,status,poll.job,tasks.service,stop,finish,store}.ts`, `tools/builtins/sandbox/{task-output,task-stop,task-list,bash}.ts`, focused background/tool tests and `test/background/permission-lifetime.dual.test.ts` (register in container list).

TaskOutput uses retained positional output, persisted monotonic readOffset, and a 4,096-byte parser-history window assembled across bounded reads when necessary. It advances only by raw bytes actually delivered as text: a live incomplete suffix is withheld; at a verified terminal stream end all remaining bytes are consumed with the existing replacement decoding. Follow the handoff's small-frame algorithm, not a single clamped overlap read. Preserve existing blocking timeout/run budget and login-code extraction. HTTP uses metadata N then sequential bounded reads assembling the entire requested suffix ending at N; later growth cannot change that captured endpoint. Neither terminal path gets the tail method's 20-line cap. TaskStop and finish summaries use tail, capped at 20 terminal lines and the existing 4,000-character event limit. Exact mappings and access distinctions are in the handoff.

Poll and stop use only exact refs and recorded instances. Five-second graceful stop remains. already-exited, stopped, cancel-pending and lost stay distinct; no false stopped event on a pending cancellation. Preserve exactly-one conditional finish/event, reported=true suppression, person/deletion no-wake behavior and durable wake outbox. Retain uncertain launch/cancel records past ordinary output pruning. Keep unavailable-provider behavior and no-resume reads/stops. An event fallback is a labeled terminal summary, never manufactured unread bytes or cursor progress.

Proposed gates: 200 KiB burst/disconnect, repeated identical bytes, >20 lines before first read, split/invalid UTF-8 and login codes, concurrent replica reads/finishes, expiry, malformed generation/ref, cross-org/cross-conversation access, HTTP ancestor access, unavailable devices and event fallback. No new exec scope or resume occurs during output/control. Compare tool/HTTP schemas and user-visible status semantics explicitly.

## Phase 8.4 — real process lifetime, cancellations and drain

Files: `device/{cli,client,server-ops}.ts`, `commands/{start,drain,stop}.ts` as needed, accepted backend lifecycle interface, kernel `runtime/{waits,run-deletion}.ts`, background stop/outbox consumers, `roles/worker.module.ts` and registry. Implement owner-ceiling persistence/CLI/server writers from the handoff before replacing old executors.

Production bootstrap uses the handoff's authenticated post-commit bindInstance/report handshake and canonical installed-byte manifest to own one trusted backend/supervisor per exact instance generation, strict owner reader and runtime identity. A pre-instance hello is unbound and cannot attest usable operations. Keep its watcher alive while any acknowledged worker, output collector or pending cancellation is owned, including idle socket/disconnection. Successful local policy writes trigger reconciliation immediately; strict file-change checks remain independent of socket policy publishing. Conversation-profile narrowing does not revoke a running task's starting grant. Actual owner/device revocation cancels affected exact owners, preserving unaffected siblings and independent host grants.

Separate RPC cancellation from task ownership: pre-ack abort records/reconciles uncertain start; after acknowledgment, disconnect/finished start RPC does not kill the task. Machine stop/revocation explicitly cancels owned work and awaits settlement; no PID/tag scan. Graceful drain rejects new admissions but allows status/read/tail/stop/reconciliation and retry/recovery of already admitted IDs. It waits for live acknowledged tasks, collectors, pending exact cancellations and accepted output/deferred persistence to settle, then disconnects. Drain timeout reports pending and remains non-reusable; it cannot declare drained from `running.size === 0`. Forced shutdown retains durable uncertainty if cancellation cannot be established.

Preserve root tasks outliving normal root run completion; sub-agent and deletion cleanup select the intended task/run set. A foreground lease-holder's cancellation must never target an acknowledged task tag. Proposed gates use two actual tasks and actual client lifecycle: one stopped/revoked, sibling retains original filesystem/network grant; lost owner, quiet worker with another blocked journal, stop while output credit starved, disconnected owner edit, graceful drain with start RPC already ended, repeated cancellation delivery and real sub-agent/deletion paths. Device component tests alone do not prove these callers.

## Phase 8.5 — legacy retirement and fail-closed reuse barrier

Files: new `background/retire-legacy-tasks.job.ts`, durable retirement schema/store, `sandbox/sandbox.service.ts`, worker/outbox registration, `test/background/protocol-upgrade.test.ts`; old executor/reaper removal is coordinated with phase 8.6.

Enumerate every legacy row: running SID, reserved null-SID with possible dispatch, stopping, kill_pending (including already terminal UI rows), and suspended/offline generations. Persist a retirement obligation keyed by device/provider/exact old instance incarnation. Never convert SID/PID/output text to a trusted new execution ref. Preserve task finish/event semantics separately from the physical no-reuse obligation; retention deletion cannot remove that obligation.

Before enumeration, publish a durable legacy-launch freeze under the existing platform authority writer, fence all replicas and pending producers, and prove every legacy launch path checks it immediately before dispatch (including previously reserved rows). Do not release an old unfenced replica into the cutover; stop/drain it first. Re-scan under that stable freeze until no new row/dispatch can appear behind the sweep. Then drain work through its actual still-owned legacy executor where exact live ownership exists. A stored SID alone is not authority to signal a process. Without such ownership, quarantine the old incarnation. Cloud retirement may use existing exclusive whole-instance destroy and require provider-confirmed destruction before fresh creation; preserve filesystem per existing policy. Local destroy is a no-op and service restart alone does not prove descendants gone. Local rows lacking trusted termination evidence stay quarantined until trusted machine/OS-instance replacement evidence proves the old processes cannot exist. No process scan, bare PID kill, optimistic timeout or new claimed generation clears them. The plan does not authorize machine reboot.

The same durable gate is checked under the exclusive lifecycle lease on ordinary use, resume, rebuild, reconnect and provider switch, before downgrade to shared/new admission. A failed kill/destroy/verification keeps the obligation and returns unavailable; logging then reusing is forbidden. A suspended instance must not execute legacy work on resume: terminate the old incarnation before reuse or leave it quarantined. Offline obligations survive reconnect and pruning. Worker processing is retryable and bounded, but its absence cannot bypass the inline gate.

Proposed gates: pre-upgrade SID/null-SID/kill_pending fixtures; failed cleanup blocks every acquire path; suspended/offline no resume, no new launch; cloud destroy failure; local no-op destroy cannot clear; reused provider handle with changed generation; concurrent retirement and acquisition across replicas; no sibling cancellation via broad killAll. A quarantined device is safely unavailable, not evidence that its tasks were successfully retired. Release gates report unresolved obligations honestly.
