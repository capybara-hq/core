# UI Slots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. With more than five tasks, plan the waves with the `wave-planned-subagent-development` skill (AGENTS.md). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extensions put UI into named, versioned slots from one SDK catalog instead of the closed `place` enum. Three new slots (agent page, org settings, admin console) arrive, and org admins and the super admin can hide and reorder contributions.

**Architecture:** The SDK owns `UI_SLOTS` (contract per slot), slot refs, structural validation (throws) and slot resolution (never throws: unknown slots are dropped). The kernel resolves slots when it loads an extension, keeps the dropped list for the admin, and gates every UI route by the slot's role and scope. That includes new org-less `/api/v1/admin/ui/*` routes for `platform.page` and embed tokens that carry their scope. The kernel also applies the org / platform arrangement to the lists. The web renders every contribution through one `ExtensionSlot` in apps/web, checked by `check:ui-slots` and `web-ui-extension-slot`. `place` is still accepted as a deprecated input (step A of the spec's three steps).

**Tech Stack:** TypeScript, zod (SDK, kernel DTOs), NestJS + Fastify + Kysely (kernel), Next 16 / React 19 + TanStack Query (web), vitest, Playwright, acorn-based source checks (`tools/checks`).

**Spec:** `docs/superpowers/specs/2026-11-08-ui-slots-design.md` (read it with this plan; § numbers below are the spec's; R1-R12 are the rulings recorded there).

- Deprecated `place` → slot (step A only): `panel` / `conversation` → `conversation.panel`, `section` → `conversation.properties.section`, `inline` → `conversation.tool-result.card`, `page` → `org.page`, `file-preview` → `file.preview`.
- Arrangement key `<extension>/<contribution>` matching `^[a-z][a-z0-9-]{1,40}\/[a-z][a-z0-9-]{0,39}$`. Entry `{ hidden: string[]; order: string[] }`, each list ≤ 200. Org setting `uiArrangement`, deployment setting `uiArrangement`, both `Record<UiSlotId, entry>`. The org arrangement refuses `platform.page`; neither arrangement takes `file.preview`.
- Access: every org UI route keeps `@OrgAction("ui.use")` (guest) and the slot's `minRole` tightens it. Admin UI routes are `@SuperAdmin()` and human only (`requireUser`). Anything refused for a contribution that exists is 404 `ui.not_found`, the same answer as a contribution that does not exist. No new error codes.
- Hidden (arrangement) means **not listed**; the view / action / embed / stream routes do not read the arrangement (spec §5).
- `apps/web` writes no styles (`check:web-ui`) and imports no SDK: it reads slot specs only from the generated `apps/web/src/lib/ui-slots.generated.ts`. Every read is a `defineQuery`, every write `useAppMutation`, and the page shape is thin server `page.tsx` + client `view.tsx`. Never a box inside a box (`findNestedBoxes` in the new web tests).
- zh UI copy says 平台 / 超级管理员 / 智能体, never 企业 or the Latin word `agent` (`check:i18n`). New strings go into `apps/web/messages/{en,zh}.json`: 未生效的界面, 界面位置, 跟随平台, 隐藏, 上移, 下移, 扩展 (admin nav group).
- New web unit tests are named `apps/web/test/ui-slot-*.test.tsx`; `apps/web/test/extension-slots.test.tsx` is an existing, unrelated test (R12).
- Before 0.1.0: no compatibility layers beyond step A's `place` input (no `legacyPlace`, no `place` in any API output).

## Review Focus

1. **A guest (or a member) reaching a slot above its role through a direct URL.** A guest hitting `GET /orgs/:orgId/ui/views/<plugin>/<org.page id>`, the action, the embed-token route or the org stream must get 404 `ui.not_found`. So must a member for an `org.settings.section` view, and anyone, super admins included, for a `platform.page` contribution through any org route. A non-super-admin on `/api/v1/admin/ui/*` gets `forbidden`. Tests in Tasks 5 and 6.
2. **A contribution in an unknown slot taking down the extension.** `{ slot: "nowhere.at-all" }` or `"conversation.panel@2"` must leave the extension loaded with its tools and other UI. The contribution shows only in `uiDropped` on the admin detail and in one warning per load. Tests in Tasks 2 and 4.
3. **The `todo` bootstrap plugin on rc.2, still declaring `place`.** A fixture shaped exactly like its manifest (`panel`, `section`, `inline`, the `conversation` alias `tasks`) must load with all four contributions and pass the static-manifest comparison. It must list them under the mapped slots, serve the alias, and keep `todo__write`'s `card` accepted by the pipeline. Tests in Tasks 4 and 5.
4. **Hiding bypassed by a direct view URL.** Decided: hidden = not listed, still served (spec §5). Tests pin both halves: the contributions list and the sidebar drop a hidden `org.page`, and its direct `/p/<plugin>/<id>` still renders for a member. A reviewer who wants "not served" must change the spec, not the gate. Tests in Tasks 7 and 15.
5. **An embed token minted for one scope used in another.** An org token (`scope: "org"`) for an `org.page` must verify null when presented for a `platform.page` contribution; a platform token must verify null for any org contribution and after the account loses super admin. An `org.page` token must verify null after the holder is demoted to guest, and an `org.settings.section` token after demotion below admin. A claims object with `scope: "platform"` and an `orgId` must fail to parse. Tests in Tasks 5 and 6.
