# Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. With more than five tasks, plan the waves with the `wave-planned-subagent-development` skill (AGENTS.md). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plugins carry declarative themes (token overrides, fonts, logo) that the platform, an org and a person can pick, rendered server-side with no flash.

**Architecture:** The SDK owns the theme format, the token allowlist and the readability check (generated from `docs/design/tokens.json`). The kernel stores themes as a fourth platform component kind (`theme`) beside skills, connector templates and agent templates, resolves the person / org / platform choice, and renders an immutable `theme.css` per version on public routes. The web links that stylesheet in the workspace and auth layouts and passes the theme's brand to the design system through its context.

**Tech Stack:** TypeScript, zod (SDK), saxes (SVG parsing in the SDK), NestJS + Fastify + Kysely (kernel), Next 16 / React 19 + TanStack Query (web), vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-08-themes-design.md` (read it with this plan; § numbers below are the spec's).

## Global Constraints

- Run single tests from the repo root: `pnpm exec vitest run <path>`; finish each task with `pnpm typecheck`, `pnpm lint`, and `pnpm check` when the task touches a checked area.
- Kernel code follows `check:kernel-conventions`: `@Injectable` providers in one module each, explicit `@Inject` on every constructor parameter, DTOs via `createZodDto` with `@ZBody` / `@ZQuery` / `@ZParam`, writes in `@Transactional()` methods, side effects in `afterCommit`, config through `KernelConfigService`.
- Migrations: next numbers `0102` and `0103` (renumbered after merging main); `IF [NOT] EXISTS`; a dropped / re-added CHECK carries the `capybara:allow-destructive` comment with its reason; applied files are never edited.
- Theme ids match `CATALOG_ITEM_NAME_RE`; limits (§4.4): file ≤ 64 KB, ≤ 10 themes per plugin, assets ≤ 16 MB per plugin; fonts ≤ 8 per theme, woff2 ≤ 2 MB each; logo SVG ≤ 128 KB, PNG ≤ 256 KB and ≥ 64 px high; wordmark ≤ 24 characters; radius 0-16 integers.
- Overridable tokens (§4.1): every `color` token except `avatar-*` and except tokens whose value is a `color-mix(…)` (they derive through `var()`, e.g. `accent-tint`); every `shadow` token; `radius` `sm` / `md` / `bubble`. Generated, never hand-listed.
- Settings keys: platform `uiTheme: { id: string | null }` in `DEPLOYMENT_SETTINGS`; org `theme: { id: string | null; personal: "allowed" | "locked" }` in `OrgSettingsSchema`; person `accounts.theme text NULL`.
- Error codes (§9): `theme.invalid` 400, `theme.unreadable` 400, `theme.not_available` 400, `theme.platform_default` 409, `theme.not_found` 404; each with en and zh copy under `errors.*` in `apps/web/messages/{en,zh}.json`.
- zh UI copy says 平台 / 超级管理员, never 企业 (`check:i18n`); 主题 / 配色 / 外观 as in §3.
- `apps/web` writes no styles (`check:web-ui`); new visuals are design components.
- SDK public API changes: `pnpm gen:sdk-api` + a changeset bumping `@capybara-hq/plugin-sdk`; `plugin-tools` / `kernel` changes get changesets too.
- Before 0.1.0: no compatibility layers (`PUT /me/preferences` simply becomes partial).

## Review Focus

1. **A theme that changes only `bg`** must still fail when `muted` / `disabled` / `faint`-floored pairs drop below their floors on the new ground (checks run on the merged scheme) — test in Task 2.
2. **A value crafted to escape CSS** (`#000;}body{display:none`, `</style>`, a family `x;}*{`) must be rejected at parse time and can never appear in `theme.css` — tests in Tasks 2 and 9.
3. **The theme that is the platform default losing `all`** through any path (component own scope, plugin scope it follows, disable, uninstall, org-owned deletion) must be refused with `theme.platform_default` — tests in Task 7.
4. **A person's pick that is off in the current org, or an org that locks**, must fall back silently to the org / platform / built-in theme, never error or show the picker — tests in Task 8.
5. **Changing a theme** must swap the stylesheet without a reload and without a flash on the next document (immutable URLs per version, cache invalidated) — e2e in Task 13.
