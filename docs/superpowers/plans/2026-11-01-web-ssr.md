# Web: server-decided first paint — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every route, layout and page of `apps/web` decides its first paint on the server; the setup
layout becomes left / right.

**Architecture:** the Proxy renews sessions and gates sign-in. Layouts and pages are server
components that read the kernel through an isomorphic `apiFetch` with a server transport, and render
client views with the data as props. Mutations stay on `/api` and end with `router.refresh()`. A
ratcheted check (`SSR_PENDING`) tracks the pages not migrated yet, until it is empty.

**Tech stack:** Next 16.4 App Router (server components, Proxy, `React.cache`, `useLinkStatus`),
React 19, the kernel HTTP API, vitest (jsdom and node projects), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-01-web-ssr-design.md` (read it first; section numbers
below refer to it). Also `docs/superpowers/specs/2026-10-31-web-order-design.md` §3.8 and §9 (setup
roles, page roles).

## Review focus

1. **An expired `cap_at` with a valid `cap_rt`** on a hard load, and on a client navigation (an RSC
   request): signed in, no sign-in page. Owned by Task 3 (proxy tests) and Task 12 (e2e).
2. **Parallel requests at expiry** (prefetches, two tabs): one kernel refresh, nobody signed out.
   Task 3.
3. **The kernel down or starting**: no redirect to sign-in. "内核正在启动" with auto-retry. Tasks 3
   and 5.
4. **Org switch, create, leave or delete from any page**: the old page stays until the new frame is
   ready; never a shell painted and then replaced. Tasks 5 and 12.
5. **A member in an unready org opening a non-setup route** (`/evals`): a server redirect to `/`,
   with no evals request sent to the kernel. Task 2 (`workspace()`), Task 11.

**Interfaces (produced):**
- `lib/api.ts`:
  - `type ApiTransport = (path: string, init: RequestInit) => Promise<Response>`;
  - `setApiTransport(t: ApiTransport | null): void`;
  - `apiFetch` uses the transport when `typeof window === "undefined"` and one is set (no refresh
    retry on the server). Without one on the server it throws
    `Error("apiFetch on the server without a transport")`.
- `lib/server/kernel.ts` (`import "server-only"`): `serverTransport: ApiTransport`.
  - Rejects non-GET.
  - Forwards `cookie`, `accept-language`, `x-request-id` and the trusted peer as `x-forwarded-for`.
  - Uses `cache: "no-store"` and a 10 s timeout.
  - Wraps GETs with `React.cache` keyed by path.
  - When the request header `x-cap-session: unavailable` is set (from the proxy), throws
    `ApiClientError(0, "upstream_unavailable", …)` without calling the kernel.
- `lib/server/register.ts`: calls `setApiTransport(serverTransport)` once.
- `lib/server/page.ts`:
  - `read<T>(p: Promise<T>): Promise<T>`, the error mapping of spec §2.3: 401 `auth.*` →
    `redirect(loginPathFor(path))`, using `x-cap-path`; 404 → `notFound()`; anything else rethrows;
  - `optional<T>(p: Promise<T>): Promise<T | null>`;
  - `currentPath(): Promise<string>`.
- `lib/server/session.ts`:
  - `getSession(): Promise<{ me: Me; org: Membership | null }>` (cached);
  - `getShell(): Promise<ShellData>`, where
    `ShellData = { me; org; readiness: OrgReadiness | null; groups: ConversationGroupsPage | null; pending: { count: number; more: boolean } | null; extensions: UiContribution[] | null }`.
    `readiness` comes back as `null` only when there is no org;
  - `workspace(opts: { min?: "guest" | "member" | "admin"; setup?: "home" | "step" }): Promise<{ me; orgId: string; role; noAccess?: undefined } | { noAccess: true; need: "member" | "admin" }>`.
    With no org it returns the chooser case by rendering nothing; the frame shows the chooser, and
    pages receive `{ noOrg: true }` and return `null`. In setup on a route without `setup` it calls
    `redirect("/")`;
  - `admin(): Promise<{ me } | { noAccess: true; need: "enterprise" }>`.
- `lib/routes.ts`:
  - `PUBLIC_PREFIXES = ["/login", "/setup", "/invite", "/bind"]`;
  - `isPublicPath(path: string): boolean`;
  - `isAdminPath(path: string): boolean`.
- `lib/use-load.ts`: `useLoad(load, deps, opts?: { initial?: T })`. With `initial` the first state is
  `ready`, there is no fetch on mount, and it fetches when the deps key changes or on `reload()`.
- `lib/use-server-state.ts`: `useServerState<T>(initial: T): [T, (v: T) => void]`. It resets when
  the `initial` reference changes.
- `test/support/server.tsx`:
  - `serverRoutes(routes)` installs a stub transport (same route syntax as `stubApi`) and returns
    the calls;
  - `renderServer(element)` renders a server page's returned element inside the providers;
  - `expectNoFirstPaintFetch()` installs a `stubApi` that throws on any browser call.

- [ ] Failing tests:
  - the transport forwards the cookie and peer and refuses POST;
  - `React.cache` deduplication (two `getMe` calls in one request → one call; use `cache` in the
    test through a request scope, or test the wrapper directly);
  - `read` maps 401, 404 and other errors;
  - `workspace` returns no-access below `min`, redirects in setup, and returns org data when ready;
  - `useLoad` with `initial` does not fetch on mount and refetches on a deps change.
- [ ] Implement. Commit `feat(web): server data layer for server-rendered pages`.

### Tasks 7–11: Migrate pages (one batch each)

Every page follows spec §6.1:
1. `page.tsx` becomes a server component: `workspace({ min, setup })` / `admin()`, parallel
   `read(...)` / `optional(...)`, `searchParams` / `params` from props, returning the view.
2. The client code moves to `view.tsx`, takes `initial` props, and uses `useLoad({ initial })` /
   `useServerState`. Mutations either update local state or call `router.refresh()` in a
   transition.
3. Role gates move from `RoleGate` / `AdminGate` wrappers to the server gate.
4. Its `SSR_PENDING` entries are removed.
5. Its tests:
   - one server test per page (first render complete, no browser fetch; the gate's no-access and
     redirect cases where it has a gate);
   - the existing client tests are switched to render the view with `initial` props.
