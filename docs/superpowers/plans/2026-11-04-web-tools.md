# Web Tools (core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kernel builtin tools `WebSearch` / `WebFetch` (Claude Code names and parameters) backed by
two new org-scoped, brokered extension points `web-search@1` / `web-fetch@1`, with a general
per-org default-provider mechanism.

**Architecture:** The SDK declares the two provider contracts and an `org-default` selection flag
for extension points. The kernel resolves an org's provider per call (`ExtensionPointDefaults`,
PG-backed, no process cache), passes the org's decrypted `orgConfig`, and runs the tools through
the normal pipeline; `WebFetch` extracts with one model call on the new purpose `web_fetch`, logged
as a `usage` event. The web gets a default-provider select and shows the web tools in the agent
form when a provider resolves.

**Tech Stack:** TypeScript, NestJS + Fastify kernel, Kysely/PG, Redis (ioredis), zod, vitest,
Next (apps/web) with `@capybara-hq/design`.

**Spec:** `docs/superpowers/specs/2026-11-04-web-tools-design.md` (read it with this plan). This
plan covers core only (spec §13 step 1). The `jina` plugin (spec §11) gets its own plan in
`capybara-hq/plugins` after the core release.

## Global Constraints

- Tool keys exactly `WebSearch`, `WebFetch`; parameters `query`, `allowed_domains`,
  `blocked_domains` / `url`, `prompt` (spec §3).
- Both tools: `defaultPolicy: "ask"`, `annotations: { readOnlyHint: true, openWorldHint: true }`;
  not on `R3_FIXED_ASK_TOOL_KEYS`.
- Specs are fixed text (no date, nothing per org / provider); `Search date: YYYY-MM-DD (UTC).` is the
  first line of every `WebSearch` result.
- Extension points: `web-search` and `web-fetch` are `multi`, brokered, `orgScoped`,
  `selection: "org-default"`.
- Model-visible text is English and passes `tool-description` / `tool-error-actionable`
  (`pnpm check`); UI text goes through i18n (zh + en); apps/web writes no styles.
- Kernel conventions (`pnpm check:kernel-conventions`): `@Injectable` providers, `@Inject` on every
  constructor parameter, `createZodDto` + `@ZBody` / `@ZParam`, writes in `@Transactional()`,
  Redis calls after commit, no process-memory state.
- Migrations: `NNNN_<snake>.sql`, `IF NOT EXISTS`; next number is `0064`.
- New comments in English. Conventional Commits; changesets for `@capybara-hq/plugin-sdk`,
  `@capybara-hq/kernel`, `@capybara-hq/web` (`fixed` with `@capybara-hq/capybara`).
- Run tests from the repo root: `pnpm exec vitest run <path>`.

## Review Focus

1. **The stored default is disabled, then re-enabled** — while disabled, the remaining candidates
   decide (one → it, several → `ambiguous`, never a silent pick); re-enabling restores the stored
   default without the admin choosing again. Test in Task 2.
2. **A provider ignores `signal` or throws a plain `Error`** — the call still ends at the tool
   timeout and the model gets the pipeline's generic failure, never the provider's message. Test in
   Task 5.
3. **A provider returns junk results** (relative URLs, `javascript:` / `ftp:` schemes, empty title,
   duplicates) — dropped before rendering; zero left renders "No results." not an error. Test in
   Task 5.
4. **An empty or enormous page** — empty `markdown` gives the tool error "The page has no readable
   text; try another URL."; over `web.fetch.maxPageChars` is cut with `[truncated]` before
   extraction. Test in Task 6.
5. **Provider switch keeps grants** — an `always` grant on `WebFetch` still applies after the org's
   default changes to another provider (same `specHash`). Test in Task 4.
