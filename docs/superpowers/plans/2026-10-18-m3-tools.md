# M3 工具与连接器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** agent 能调用工具：内置工具、插件提供的工具、组织安装的应用（MCP / OpenAPI）里的工具；每次调用经过统一的执行管线与工具策略，「询问」类调用暂停运行、由发起人审批后从快照续跑；认证由内核托管（静态凭据与 OAuth），凭据不进模型、不进日志。验收：agent 调 MCP / OpenAPI 应用，写操作触发审批，审批后继续。

**Architecture:**
- **三层不变**：协议在插件（`connector@1`：`connector-mcp`、`connector-openapi`），内核负责应用安装、凭据与认证注入、工具注册表、策略、执行管线、审批、审计、输出存档；插件自带的工具经 `ctx.tools` 注册（`todo` 插件是第一个例子）。
- **工具调用进日志**：新事件 `tool_call_started` / `tool_result` / `approval_requested` / `approval_decided` / `question_asked` / `question_answered`；请求构建从这些事件还原 `tool_call` / `tool_result` 块；`model_call` 记录本次请求所用工具定义的指纹，任何一次模型请求仍可由日志 + agent 版本 + 工具快照还原。
- **暂停与续跑**：运行遇到需要人处理的调用（审批、提问）时写事件、保存快照、以 `suspended` 结束本次执行，run 状态变为 `waiting`，释放 worker、会话锁与组织配额；处理结果（或超时）把 run 重新入队，从快照续跑。
- **大结果**：超过阈值的工具结果存为「输出存档」（`tool_outputs`，内核概念，与沙箱、产物无关），日志与模型只见摘要 + id；`read_tool_output` 分页读，参数中 `{"$output": "<id>"}` 引用全文。
- **两段执行**：第一段（Task 1–14）跑通「静态认证的 MCP + 审批」闭环并可单独验收；第二段（Task 15–24）补 OpenAPI、OAuth、漂移检测、`tool_search`、MCP 其余能力与安装向导。一个分支，最后一起合并。

**Tech Stack:** 同 M2；新增 `@modelcontextprotocol/sdk`（MCP 客户端，插件内；测试夹具用其服务端）、`ajv`（内核，JSON Schema 2020-12 校验工具参数）、OpenAPI 解析选 `@apidevtools/swagger-parser` 或等价的维护中库（Task 18 定，记入报告）。

**Spec:** `docs/superpowers/specs/2026-10-17-capybara-architecture-design.md` §2.3–2.4、§3.6、§4.2–4.3、§4.6、§5、§6.3–6.7、§7.3（Task 1 按本计划修订 §2.3、§5.4 并补「插件扩展界面」待定项）。设计系统：`docs/design/spec.md`、`skills/writing-web-ui/SKILL.md`。用户确认的决策 D1–D14 见下文「决策摘要」。

## Global Constraints

- 沿用 M2 主计划（`docs/superpowers/plans/2026-10-17-m2-agent-runtime.md`）的 Global Constraints 全文与 M2 补充计划的约束；重点：插件只 import `@capybara-hq/plugin-sdk` 与第三方包；多副本纪律（状态进 PG / Redis、Redis 写入带 TTL、内核键前缀 `capk:`、队列名与 job id 不含 `:`、进程内定时器只用于本进程持有的资源）；内核 HTTP 默认拒绝、`lockOrgAndAuthorize`、错误码登记在 `errors.ts`；**模型可见文案一律英文**；**事件日志只追加**；**发给模型的历史只追加**；任意一次模型请求可由日志还原；界面文案 i18n（zh / en 同步）；每道新增自动检查先证明会红。
- **工具名（模型可见）**：`^[a-zA-Z0-9_-]{1,64}$`。内置：`ask_user`、`read_tool_output`、`tool_search`；插件工具：`<plugin>__<tool>`；应用工具：`<appSlug>__<tool>`（`appSlug` 为安装时生成的 `^[a-z][a-z0-9_]{0,23}$`）。超长或冲突在保存 agent / 安装应用时报 `validation_failed`，不截断、不猜。
- **凭据**：只存在 `capybara.secrets`（命名空间 `credentials`，键 `app:<appId>:org` / `app:<appId>:user:<accountId>`，值为 JSON），解密后只在注入请求头的那一刻出现；所有凭据值注册到日志打码；错误信息、事件、审计中只出现凭据**类型与归属**，不出现值。
- **策略取值顺序**：`allow < ask < deny`；agent 负责人只能收紧；spec 3.6 R3 清单与 `requiresUserInteraction` 的工具至少为 `ask`；记住的授权只能把 `ask` 放行为 `allow`，不能越过 `deny`。
- **失败即拒绝**：审批超时、审批人不存在、等待期间 run 被中止，一律按拒绝写 `tool_result`（`isError: true`，英文说明原因）。
- **给事实，不猜**（spec 6.3）：工具参数校验失败返回完整的错误路径 + 工具的 inputSchema；调用未加载 / 不存在 / 已停用的工具返回明确错误与可用的替代途径（`tool_search`），不做模糊匹配。
- **有副作用不盲目重跑**（spec 4.3）：调用前写 `tool_call_started`；续跑时「有开始无结果」的调用写结果 `Result unknown…`（复用 `UNKNOWN_RESULT_TEXT`），不再执行。
- **新增配置**放在新的 `tools` 段与 `http.publicUrl`（见 Task 3），走 `skills/adding-config`，重新生成 `docs/config.md`。
- **网页**：只用 `@capybara-hq/design` 模板与组件，`pnpm check:web-ui` 必须通过；缺组件按 `skills/writing-web-ui`「新增组件或模板」四步走（改 design spec → 实现 + 测试 → `/dev/ui` 目录页 → 在 PR 分支触发 `visual-update` 工作流生成 Linux 截图基准）。能用现有组件组合的不新增组件。
- **JSON Schema**：工具参数用 `ajv`（draft 2020-12，`strict: false`，`allErrors: true`）校验；模型参数仍用 M2 的自实现子集校验，不混用。

## Review Focus

1. **审批在另一个副本上被处理、或被重复处理**：同一审批只生效一次，run 只续跑一次；先「批准」后「拒绝」的第二次请求返回 `approval.already_decided`。→ Task 8 测试（双副本 + 并发决策）。
2. **工具执行中 worker 被杀**：续跑后该调用得到「结果未知」，工具不被再次调用；之前已有结果的调用不重复执行。→ Task 7 测试。
3. **凭据泄露**：MCP 服务把收到的 Authorization 头回显在错误或结果里、日志打印请求失败详情时，凭据值不出现在事件、日志、审计、HTTP 响应中。→ Task 11 测试。
4. **工具被删除或停用后，引用它的旧 agent 版本继续运行**：运行时跳过不可用工具并写一条英文 `reminder` 说明哪些工具不可用，模型调用它时得到明确错误；不让整轮失败。→ Task 6 测试。
5. **MCP 服务慢、挂、返回超大或畸形结果**：超时返回可执行的错误；连续失败熔断并告诉模型多久后重试；超大结果转存；非文本内容（图片等）给出类型说明而不是丢弃。→ Task 7、Task 12 测试。

export interface ToolAnnotations { readOnlyHint?: boolean; destructiveHint?: boolean; idempotentHint?: boolean; openWorldHint?: boolean; requiresUserInteraction?: boolean }
export interface ToolSpec { name: string; description: string; inputSchema: Record<string, unknown>; annotations?: ToolAnnotations; defaultPolicy?: "allow" | "ask" /* 仅插件 / 内置工具可声明；缺省按注解推导 */ }
export type ToolContent = { type: "text"; text: string } | { type: "image"; mimeType: string; data: string } | { type: "resource_link"; uri: string; name?: string; mimeType?: string };
export interface ToolResult { content: ToolContent[]; isError?: boolean }
/** 交互表单：字段的 schema 只用 M2 的 ParamSchema 子集（枚举 / 布尔 / 带范围的数字 / 字符串）；枚举字段可设 multiSelect 与 allowOther。 */

  fields: { key: string; label: { zh: string; en: string } | string; description?: { zh: string; en: string } | string; schema: ParamSchema; multiSelect?: boolean; allowOther?: boolean; required?: boolean }[];
}
/** 工具需要用户输入：内核暂停运行、渲染表单；用户提交后用同一 input 再次调用该工具，并在 ctx.resume 中带回 state 与 answer。state ≤ 16 KB，可 JSON 序列化。 */
export interface InputRequired { kind: "input_required"; form: InputForm; state?: unknown }
export interface ToolCallContext { orgId: string; accountId: string; agentId: string; conversationId: string; callId: string; signal: AbortSignal; resume?: { state: unknown; answer: Record<string, string | number | boolean | string[]> | null /* null = 用户取消或超时 */ } }
export type ToolHandler = (input: unknown, ctx: ToolCallContext) => Promise<ToolResult | InputRequired>;
export class ToolError extends Error { constructor(message: string /* English, actionable */) }
// ctx.ts 增加
tools: { register(spec: ToolSpec, handler: ToolHandler): void };
// connector.ts —— 插件实现、内核调用
export interface AuthInjection { headers: Record<string, string>; query?: Record<string, string> }
export interface ConnectorSession { listTools(): Promise<ToolSpec[]>; callTool(name: string, input: unknown, signal: AbortSignal): Promise<ToolResult>; listResources?(): Promise<{ uri: string; name: string; description?: string; mimeType?: string }[]>; readResource?(uri: string): Promise<ToolResult>; close(): Promise<void> }
export interface ConnectorOpenArgs { endpoint: unknown /* 已按 endpointSchema 校验 */; auth: () => Promise<AuthInjection> /* 每次请求前调用，内核负责刷新 */; onUnauthorized: () => Promise<void> /* 401 时调用一次，内核刷新后插件重试一次 */; signal: AbortSignal }
export interface Connector { kind: string; endpointSchema: ZodTypeAny; open(args: ConnectorOpenArgs): Promise<ConnectorSession> }

### Task 15: OAuth（授权码 + PKCE、MCP OAuth 发现与 DCR、客户端凭据、刷新加锁）

```ts
export type OAuthAuth =
  | { type: "oauth_code"; ownership: "personal"; discovery: "mcp" | "manual"; authorizationUrl?: string; tokenUrl?: string; scopes?: string[]; client: "dcr" | "manual" }
  | { type: "oauth_client"; ownership: "org"; tokenUrl: string; scopes?: string[] };
```
- MCP 发现：RFC 9728 受保护资源元数据（`WWW-Authenticate` 的 `resource_metadata` 或 `/.well-known/oauth-protected-resource`）→ RFC 8414 授权服务器元数据；DCR（RFC 7591）注册的 client 按应用存入凭据（组织级）；对方不支持 DCR → 应用创建时要求管理员填 `client_id` / `client_secret`（`app.connect_failed` 携带 `dcr_unsupported` 细节，供向导提示）。
- 授权码流：`POST /api/v1/orgs/:orgId/apps/:appId/connect` 返回授权 URL（state 存 Redis 10 分钟，含 orgId、appId、accountId、PKCE verifier、回跳页面）；`GET /api/v1/oauth/callback`（`@Public`，加入公开路由清单）校验 state、换 token、存个人凭据、302 回网页。
- 刷新：access token 过期前 60 s 或收到 401 时刷新；刷新在 `capk:oauth-refresh:<orgId>:<appId>:<owner>` 分布式锁内进行，拿不到锁则等待锁释放后重读凭据（不并发刷新）；refresh 失败 → 凭据标记失效，调用返回 `credential.missing` 语义的工具错误并触发「需要连接」卡片。
- 客户端凭据流：组织级，按需取 token 并缓存于凭据存储（带过期时间）。
- `http.publicUrl` 未配置时，OAuth 类应用创建返回 `validation_failed`（path `auth`，说明需要配置 `http.publicUrl`）。

- [ ] 测试：发现链路（两种 metadata 位置）、DCR 成功与不支持、PKCE、state 过期与伪造、回调后凭据可用、双副本并发 401 只刷新一次（Review 重点）、refresh 失败 → 需要连接、token 不出现在日志与事件。
- [ ] 提交 `feat(kernel): OAuth 认证（授权码、MCP 发现与动态注册、客户端凭据、刷新加锁）`。
