# M1 身份与组织 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把内核 HTTP 层迁到 NestJS + Fastify，并实现身份与组织：账号、外部身份、组织、成员、四种角色、企业管理员、本地登录、初始化向导与 `capybara admin create`、会话与令牌、组织级插件配置存储，使「建企业管理员 → 建组织 → 邀请成员 → 按角色鉴权」在双副本下跑通。

**Architecture:** Nest（Fastify 适配器）只存在于 `packages/kernel/src/http` 与各功能目录的 `*.controller.ts` / `*.guard.ts` 中；领域逻辑是**不依赖 Nest 的普通类**（构造参数传 Kysely / Redis / Keyring），Nest 用工厂 provider 注入它们，CLI（`capybara admin create`）直接复用同一批类。插件路由不经过 Nest：在 Fastify 的一个封装作用域里以原始字节接收 `/plugins/:name/*`，转换成 Web `Request` 交给插件 handler，插件契约（`ctx.http.route`）不变。所有跨请求状态在 PG（账号、会话、令牌、邀请）或 Redis（登录失败计数、会话吊销名单，均带 TTL），不在进程内存。

**Tech Stack:** NestJS 12（`@nestjs/core` / `@nestjs/common` / `@nestjs/platform-fastify`）、Fastify 5、`@fastify/cookie`、`find-my-way`（插件路由匹配）、`jose`（access token，HS256）、`node:crypto`（scrypt 密码哈希、HKDF、随机令牌）、Kysely、Zod 4、Vitest + Testcontainers。

**Spec:** `docs/superpowers/specs/2026-10-17-capybara-architecture-design.md`（重点 3.1–3.5、2.2、8.4、10）；路线图 `docs/superpowers/plans/2026-10-17-mvp-roadmap.md`；M0 遗留 `docs/superpowers/plans/2026-10-17-m0-followups.md`。

## Global Constraints

- 包名一律 `@capybara-hq/<name>`；许可证 Apache-2.0；依赖装当时最新稳定版（以 lockfile 为准）。
- 插件只能 import `@capybara-hq/plugin-sdk` 与第三方 npm 包；**插件契约不暴露框架**：插件不写 Nest controller、不依赖 Nest 模块与 DI，`ctx.http.route(method, path, (req: Request) => Promise<Response>)` 签名不变。
- 多副本纪律：写入方与读取方可能不在同一进程的状态不得放进程内存（进程内 Map、定时器、本地事件一律不行），用 PG / Redis；Redis 写入必须带 TTL；BullMQ 队列名与 job id 不得含 `:`。
- 内核 Redis 键前缀 `capk:`（插件键是 `cap:<ns>:`，二者不可能相撞）。
- 迁移是纯 SQL 文件，命名 `NNNN_<snake_desc>.sql`；建删对象带 `IF NOT EXISTS` / `IF EXISTS`；内核 schema 为 `capybara`。
- 环境变量前缀 `CAPYBARA_`，嵌套用双下划线；新增配置项必须写 `meta`（hot / secret / description）并运行 `pnpm gen:config-docs`。
- 给模型看的文案一律英文；API 错误的 `message` 用英文，界面文案以 `code` 为 key 走 i18n（界面在 M2 起做）。
- **身份只按「来源 + 外部 ID」识别，不按邮箱**；本地账号即来源 `local`、外部 ID 为规范化后的登录名。
- Web 会话 Cookie 不写 `Domain`（仅限当前主机）；短期 access token + PG 中可吊销的 refresh token。
- 权限在动作执行那一刻判定（spec 3.6 R5）：每个请求都实时读账号状态与成员角色，不缓存在进程内存。
- Nest 规则：`experimentalDecorators` 开启、**不开 `emitDecoratorMetadata`**；因此每个构造参数都必须写 `@Inject(TOKEN 或 类)`（tsx / esbuild 与 Vitest 不产出设计期元数据，漏写会在应用初始化时报「无法解析依赖」）。
- 每道新增的自动检查（含本计划中的「公开路由清单」元测试）必须先证明会红。
- 提交信息 Conventional Commits，标题中文；提交身份 `Grant <284885069@qq.com>`。

## Review Focus

1. **两个副本同时提交初始化向导**：只有一个成功成为企业管理员，另一个返回 409 `setup.already_completed`，库里恰好一个企业管理员。→ Task 9 `concurrent setup` 测试、Task 12 双副本验收。
2. **组织仅剩两个所有者时二人同时互相降级 / 移除**：组织最终仍至少有一个所有者，后提交的请求返回 409 `org.last_owner`。→ Task 7 `concurrent demote keeps an owner` 测试（行锁串行化）。
3. **同一 refresh token 被两个标签页同时刷新、落在两个副本**：一个成功，另一个 401 `auth.refresh_race` 且会话不被吊销；宽限期（30s）外重放已轮换的 refresh token → 判定为泄露，整个会话吊销。→ Task 5 测试。
4. **在副本 A 登出后，拿同一 access token 去副本 B**：立即 401 `auth.session_revoked`，而不是等 access token 自然过期。→ Task 5 单测 + Task 12 双副本验收。
5. **同一邀请链接被并发接受两次 / 已过期 / 已撤销**：只产生一个成员；过期返回 410 `invitation.expired`，已用返回 409 `invitation.used`，已撤销与不存在一律 404 `invitation.invalid`。→ Task 8 测试。

## M1 锁定的技术选型

| 项 | 选择 | 理由 / 证据 |
|---|---|---|
| HTTP 框架 | NestJS 12 + `@nestjs/platform-fastify` + Fastify 5 | spec 第 10 节。Nest 12 是纯 ESM 包，仍用 legacy 装饰器 |
| 装饰器 | `experimentalDecorators: true`（写在 `tsconfig.base.json`），不开 `emitDecoratorMetadata`，构造参数一律显式 `@Inject` | 写计划时在 scratchpad 实测：TS 7.0.2 `tsc` 产物用 node 运行、`tsx` 直接跑源码、Vitest 5 三条链路下，Nest DI + Fastify `inject()` 全部通过；Biome 2.5 用仓库现有配置可解析参数装饰器 |
| 插件路由 | Fastify 封装作用域 + 通配内容类型解析器（`parseAs: "buffer"`）收原始字节；`find-my-way` 匹配插件注册的路径 | 同一次实测验证：表单、二进制、JSON 请求体在该作用域内都以原始 Buffer 到达；插件加载晚于 Nest 初始化，不能再向 Fastify 注册新路由，所以用独立路由表 |
| 密码哈希 | `node:crypto` scrypt（N=2^15, r=8, p=1） | 无原生依赖（避免 argon2 的原生构建）；OWASP 认可的参数 |
| access token | JWT HS256（`jose`），签名密钥由主密钥经 HKDF 派生，`kid` = 主密钥 id；有效期默认 900s | 无状态校验；主密钥轮换期间旧 token 仍可验 |
| 会话吊销 | Redis `capk:revoked-sid:<sid>`，TTL = access token 有效期 + 60s | 多副本即时生效；TTL 到期时对应 access token 也已过期 |
| refresh / PAT / 服务令牌 / 邀请 | 不透明随机串（32 字节 base64url）带前缀 `cap_rt_` / `cap_pat_` / `cap_svc_` / `cap_inv_`；库里只存 SHA-256 | 前缀便于密钥扫描器识别；库泄露不泄露令牌 |
| ID | `crypto.randomUUID()`，列类型 `text` | 与 M0 的 `org_data_keys.org_id text` 一致 |
| API 前缀 | `/api/v1`（Next web 服务把 `/api` 代理到 api） | spec 8.4 |
| 错误格式 | `{ "error": { "code": "<registered.code>", "message": "<English>", "details"?: [...] } }`；`code` 是 `errors.ts` 中登记的字面量联合类型 | 「错误码唯一」由 TypeScript 类型保证（对象键唯一 + 字面量联合），不另写检查 |
| CSRF | Cookie 认证的非 GET/HEAD/OPTIONS 请求必须带 `X-Capybara-Csrf: 1`；Cookie `SameSite=Lax`（refresh cookie 为 `Strict`）；不开 CORS | 跨站表单无法设置自定义头，不开 CORS 就无法预检通过 |

## 范围之外（M1 明确不做）

- 任何界面：初始化向导、登录页、成员管理页都只提供 API；网页在 M2 起由 Next 实现。
- 身份来源插件（飞书 / Slack / OIDC 登录）、`identity-source@1` / `directory@1` 接口、通讯录同步与离职流程（M4）。M1 只建好 `identities` 表与「来源 + 外部 ID」的唯一约束。
- 「事件在事务提交后发出」：M1 没有消费方，成员移除只在同一事务内完成撤销与审计；M4 接通讯录时再加事务后事件。
- 插件路由的调用者身份：插件路由不经内核鉴权（webhook 由插件自行验签），向插件暴露调用者身份留到 M4。
- 合规审计查看、审计导出：M1 只写 `audit_events` 表。
- 组织数据硬删除与导出（M6）：删除组织是软删除。

**Interfaces:**
- Consumes: `Route`（`ctx/create-ctx.ts`，M0）、`Logger`（plugin-sdk）。
- Produces:
  - `errors.ts`：
    ```ts
    export const ERROR_CODES = {
      internal: 500, not_found: 404, validation_failed: 400, forbidden: 403,
    } as const satisfies Record<string, number>;   // 后续任务往这里追加
    export type ErrorCode = keyof typeof ERROR_CODES;
    export class ApiError extends Error {
      constructor(readonly code: ErrorCode, message: string, readonly details?: unknown[]);
      get status(): number;  // ERROR_CODES[code]
    }
    ```
  - `http/tokens.ts`：`export const KERNEL_LOG = Symbol("KERNEL_LOG"); export const HEALTH_OPTIONS = Symbol("HEALTH_OPTIONS");`
  - `HealthOptions = { checks: Record<string, () => Promise<void>>; isStopping: () => boolean; log: Logger; timeoutMs?: number }`（与 M0 `mountHealth` 的参数相同，行为不变：`/healthz` 恒 200 `{ ok: true }`；`/readyz` 每项 2s 超时，body `{ ok, pg: "ok"|"error", redis: ... }`，停机时 503 `{ ok: false, stopping: true }`，失败原因只进日志）。
  - `createHttpApp(opts: { log: Logger; health: HealthOptions; serveApi: boolean; servePlugins: boolean; apiModule?: DynamicModule; trustProxy?: boolean }): Promise<KernelHttpApp>`
    ```ts
    export interface KernelHttp {
      inject(opts: InjectOptions): Promise<LightMyRequestResponse>;   // fastify 的类型
      /** 已注册的全部路由（Fastify onRoute 收集），供元测试遍历。 */
      routes(): { method: string; url: string }[];
    }
    export interface KernelHttpApp extends KernelHttp {
      mountPlugins(routes: Route[]): void;      // 只能调一次；路径必须以 /plugins/ 开头
      listen(port: number): Promise<number>;   // 监听 0.0.0.0，返回实际端口
      close(): Promise<void>;                  // Nest app.close()
    }
    ```
    - `NestFactory.create(RootModule, new FastifyAdapter({ trustProxy }), { logger: new NestLogAdapter(log), abortOnError: false })`，`await app.init()` 在 `createHttpApp` 内完成（不连接任何外部资源）。
    - `RootModule` 动态组装：总是含 `HealthController`；`serveApi` 为 true 且给了 `apiModule` 时 import 它。全局 `APP_FILTER` = `ErrorFilter`。
    - `servePlugins` 为 true 时调用 `registerPluginDispatch(fastify, getRoutes, log)`（在 `app.init()` 之前）。
  - `registerPluginDispatch(fastify: FastifyInstance, getRouter: () => PluginRouter | undefined, log: Logger): Promise<void>`：
    - 在 `fastify.register(async scope => …)` 封装作用域内：`scope.removeAllContentTypeParsers()`；`scope.addContentTypeParser("*", { parseAs: "buffer" }, (_r, body, done) => done(null, body))`；`scope.all("/plugins/*", handler)`。
    - `PluginRouter`：`mountPlugins` 时用 `find-my-way` 建立，路径语法与 Fastify 相同（支持 `:param`，但 handler 只拿到 Web `Request`）。未挂载、无匹配 → 404 错误信封 `not_found`。
    - Fastify → Web：`new Request(\`http://${req.headers.host ?? "localhost"}${req.url}\`, { method, headers, body })`；GET/HEAD 不带 body；数组头用 `, ` 合并（`set-cookie` 除外）。
    - Web → Fastify：`reply.code(res.status)`；逐个复制响应头，`set-cookie` 用 `res.headers.getSetCookie()` 逐条设置；`res.body` 为 null → `reply.send()`，否则 `reply.send(Readable.fromWeb(res.body))`（为 M2 流式留路）。
    - handler 抛错 → 记 `log.error("plugin handler failed", { path, err })`，返回 500 `{ error: { code: "internal", message: "Internal error" } }`，不回显错误信息。
  - `ErrorFilter`：`ApiError` → `{ status, { error: { code, message, details? } } }`；Nest `HttpException`（如路由不存在的 404）→ 对应状态码 + `not_found` / `validation_failed` / `internal`；其他异常 → 500 `internal` 并记日志。
  - `Kernel` 接口变更：删除 `readonly app: Hono`，新增 `readonly http: KernelHttp`。`createKernel` 中以 `serveApi: roles 含 api`、`servePlugins: roles 含 api 或 gateway` 调用 `createHttpApp`；`start()` 里 `mountPlugins(host.routes())` 后，角色含 api 或 gateway 时 `listen(config.http.port)`（Task 2 改为总是监听）；`doStop` 的 HTTP 阶段改为 `httpApp.close()`。
