# Capybara 0.1.0

The first release of Capybara, an open-source enterprise agent platform (Apache-2.0). Everything below
is new: there is no earlier release to upgrade from.

## What's in 0.1.0

**Platform**

- A kernel that only does config, database, extension hosting and HTTP; every capability is an extension.
- Identity and organizations: local accounts, external identities, four roles, enterprise admin.
- Agent runtime: versioned agents, an event log as the single source of truth, BullMQ run pipeline,
  streaming, interjection, abort, crash resume, context compaction.
- Tools and connectors: tool execution pipeline, approvals, MCP and OpenAPI connectors, `tool_search`.
- Channels: Slack and Lark (long connection by default, optional webhook inbound), approval cards,
  external identity mapping.
- Object storage, attachments and media input, per-conversation sandboxes (Docker, E2B), skills.
- Evals and replay, admin console, extension lifecycle without restarts, the catalog, marketplaces
  and plugins (bundles of extensions, connector templates and skills).
- `ctx.hooks` (`model.request`, `model.response`, `tool.preExecute`, `tool.postExecute`,
  `usage.report`): observe or deny only, never rewrite.

**Packaging**

- Four images on ghcr.io, each for linux/amd64 and linux/arm64, with SLSA provenance and an SBOM:
  `capybara-api`, `capybara-worker`, `capybara-gateway`, `capybara-web`. The core image contains the
  kernel plus the `openai-compatible` and `object-store-s3` extensions only.
- `docker/compose.yaml`: api, worker, gateway, web, PostgreSQL 17, Valkey, SeaweedFS, a one-shot `init`
  that migrates and creates the first admin, and an optional Docker sandbox profile.
- npm packages with provenance: `@capybara-hq/plugin-sdk`, `@capybara-hq/kernel`,
  `@capybara-hq/testing` and every official plugin except the `example-*` ones. Their extensions are
  installed at runtime by package name.
- A public API snapshot of `@capybara-hq/plugin-sdk`, checked in CI.
- A contributor license agreement (CLA) bot; the CLA text is a draft pending legal review.

Start with [docs/deploy/README.md](../deploy/README.md).

## 0.x statement

Capybara is on 0.x. The plugin SDK (`@capybara-hq/plugin-sdk`) and the kernel HTTP API may change in
breaking ways between minor versions. Each release's notes describe breaking changes and how to
migrate. Do not depend on 0.x APIs staying stable.

## Upgrade notes

- **PostgreSQL 15 or newer is required.** `capybara migrate` refuses older servers, because migration
  0029 uses `UNIQUE NULLS NOT DISTINCT`.
- **Index builds take table locks.** Migrations 0027, 0028 and 0040 build indexes non-concurrently in
  the migration transaction, so writes to the affected tables (notably `conversation_events`) block
  until the index is built. New installs migrate empty tables. This matters only for deployments that
  ran `main` before 0.1.0 and have large event logs. See
  [docs/deploy/upgrade.md](../deploy/upgrade.md).
- **Channel long connections run on the `gateway` role.** If you set `CAPYBARA_ROLES` yourself, add
  `gateway` to at least one process.
- **The official marketplace is off by default** (`marketplaces.official.enabled: false`).
- **Terms renamed before the first release:** the in-process code is an extension, a plugin is the
  install unit (formerly an app bundle), the enterprise directory is the catalog and catalog sources
  are marketplaces; config keys, env vars, the CLI (`capybara extensions …`), HTTP routes and error
  codes follow. See [docs/deploy/upgrade.md](../deploy/upgrade.md).

## Known limitations

- **The official marketplace is not live.** Official plugins are published to npm only; install them by
  package name. The official marketplace repo and the signing of packages and marketplaces beyond npm
  provenance are deferred to the later package-ecosystem project.
- **No Gemini provider extension.** Use `openai-compatible` or the Anthropic and OpenAI extensions.
- The `sandbox` compose profile needs a repository checkout, because its two images are built locally
  and are not published.
- Extension packages installed with the CLI are stored in PostgreSQL rather than object storage.
- Deferred, not planned for 0.1.x: `session.*` and `agent.preStep` hooks, `usage.report` for
  single-step eval and judge usage, a Helm chart, `HookScope.orgConfig` / `ctx.orgConfig(orgId)` so
  hooks can read extension org config, private-network default-deny for marketplace tarball downloads, and a
  grants list API. See the M7 row of the
  [roadmap](../superpowers/plans/2026-10-17-mvp-roadmap.md).

## Unverified at release time

These were covered by automated tests (fake platforms, fake registries, dual replicas) but not run
against the real environment. Treat them as unverified. Results of the release gate are recorded in
[m7-live-acceptance-checklist.md](../superpowers/plans/m7-live-acceptance-checklist.md); failures are
added here.

- **CLA bot:** not verified on a fork PR (comment, signing sentence turning the status green, bot PR
  exemption).
- **Slack and Lark live platforms**
  ([m4 checklist](../superpowers/plans/m4-live-acceptance-checklist.md)): real-platform behavior such
  as card callbacks, long connection reconnects and rate limits, directory change events, browser
  login. The release gate covers one real connection only.
- **Sandboxes, media and skills**
  ([m5 checklist](../superpowers/plans/m5-live-acceptance-checklist.md)):
  - Docker with gVisor (`runsc`) and the Docker extension tests on a native linux/amd64 Docker host;
  - E2B live, including its recorded assumptions;
  - real-model image and PDF requests (Anthropic, OpenAI) and the `ark` dialect's image mapping;
  - the manual web flows: attachments, delivery, hibernation, egress, rebuild, skills.
- **Evals, extension lifecycle and catalog**
  ([m6 checklist](../superpowers/plans/m6-live-acceptance-checklist.md)):
  - evals with a real judge model;
  - public and private npm installs, wrong-token and registry-change cases;
  - an enterprise marketplace hosted on a real server, mirrors, and the offline mode round trip;
  - the Nacos source and its read-only display;
  - the smoke test of every official extension package tgz;
  - multi-host extension sync (upgrades while a host is down, concurrent upgrades, pub/sub loss);
  - a real plugin (bundle), including uninstall with shared components.
- **arm64 and first-publish paths:** the compose stack on arm64, npm trusted publishing (OIDC) as a
  replacement for `NPM_TOKEN`, and the first real run of the release workflow.
