目录来源（D16 / C25 / C26，`CatalogsService`，`Kernel.catalogs`）：迁移 `0035_catalogs.sql`（`catalog_sources` / `catalog_entries`；`directory_items.catalog_source_id`；`directory_item_versions.source` 增加 `catalog`）。新配置 `catalogs.official.{enabled,url,mirrors}`（默认开启，地址为 M7 前占位，`enabled=false` 即离线模式）、`catalogs.refreshIntervalMinutes`（360）、`catalogs.maxIndexBytes`（5 MiB）、`catalogs.allowInsecureLoopback`（只供测试）。official 来源启动时按配置同步；企业清单存 PG，可选令牌存 secrets（`kernel` / `_deployment` / `catalog-token:<id>`），只发往清单地址的源。拉取只认 https、不跟随重定向、有超时与大小上限、按 SDK 清单 schema 校验，主地址失败依次尝试镜像，带 If-None-Match；不合法或拉取失败保留上一份条目、状态 `error`，状态变化时审计 `catalog.refreshed` 并打一次日志。维护任务 `catalogs-refresh`（一个 scheduler 管全部副本）定期刷新全部生效的来源，某个失败不影响其他。企业管理员接口 `GET/POST /api/v1/admin/catalogs`、`PATCH/DELETE …/:id`（official 只能启停，`catalog.builtin`）、`POST …/:id/refresh`、`GET …/entries?sourceId&kind&q`（已引入 / 兼容 / 有新版本）、`POST …/:id/entries/:kind/:name/import {version}`。`DirectoryService.importFromCatalog`：版本须兼容（`catalog.incompatible`），按清单的 `tarball`（https）或 npm registry 下载，一律按清单 sha512 校验（不符 `catalog.integrity_mismatch`，写明两边前缀，什么都不写），包须与条目一致（`catalog.package_mismatch`），然后走目录导入流程（来源 `catalog`，source_ref `<sourceId>:<npm>@<version>`；插件包 ref `catalog:<sourceId>:<npm>@<version>`）；清单权限摘要与包算出的不一致时在结果里给出 `permissionsMismatch`（只警告）。新错误码 `catalog.not_found`、`catalog.entry_not_found`、`catalog.fetch_failed`、`catalog.invalid`、`catalog.integrity_mismatch`、`catalog.incompatible`、`catalog.package_mismatch`、`catalog.builtin`。`IntegrityMismatchError` 带上期望与实际 integrity。
