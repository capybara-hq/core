- MCP 交互（D4）：`ConnectorOpenArgs` 新增可选回调 `onElicit(request)`（远端在调用途中向用户要输入时调用，返回答复）；新增类型 `ElicitationRequest`（`form`：`message` + `requestedSchema`；`url`：`message` + `url` + `elicitationId`）与 `ElicitationResponse`（`accept` 带可选 `content` / `decline` / `cancel`）。`ConnectorSession` 新增可选方法 `listPrompts()` / `getPrompt(name, args)` 与类型 `PromptInfo`、`RenderedPrompt`。`InputForm` 新增可选 `url`（需要用户打开的外部页面，`validateInputForm` 只接受 ≤ 2000 字符的 http(s) 绝对地址）。旧连接器 / 旧内核不提供这些也照常工作。
- `Connector` 新增可选方法 `inspect({ endpoint, signal })`，返回 `{ authHints: AuthHint[]; operations?: ConnectorOperation[] }`（不带凭据读端点描述，供安装向导预填认证方式、勾选操作）；新增导出类型 `AuthHint`（映射到内核应用认证的形状：`bearer` / `basic` / `api_key{in,name}` / `oauth_client{tokenUrl,scopes}` / `oauth_code{authorizationUrl,tokenUrl,scopes}`，带 `scheme` 与可选 `description`）、`ConnectorOperation`、`ConnectorInspection`。旧连接器不实现也照常工作。
- 调用按已复核的定义路由（Ruling A21）：`ToolSpec` 新增可选的不透明字段 `connectorData`（仅连接器工具），内核把它存进快照（`app_tools` / `tool_specs`）并计入 spec_hash，但从不发给模型；`ConnectorSession.callTool` 新增可选第 4 个参数 `ctx: { spec }`，内核传该工具已复核的定义（`app_tools.spec`，绝不是待复核的新定义）。connector-openapi 在 listTools 时把方法、路径模板、参数位置与风格、请求体媒体类型、解析好的服务器地址写进 `connectorData`，调用只按 `ctx.spec.connectorData` 构造请求、不再读取文档（缺失时提示管理员刷新应用）——远端文档改了方法 / 路径会改变指纹、进入漂移复核，复核通过前仍走旧路由；文档只在 listTools / inspect 时读取。
  应用列表与详情的 `endpoint` 不再回显 `text` / `*Text` 字段全文（如 OpenAPI 的 `specText`），换成 `<field>Bytes` 与 `<field>Sha256`（所有人一致；要改文档时重新上传）。
- 工具定义漂移检测与复核（spec 7.3）：维护队列每 `tools.driftIntervalHours` 小时（job scheduler `drift-scan-interval`，多副本只有一个）对活动应用重新 listTools，与快照比对——新增工具 `pending_review`；定义变化 → `pending_review`（新定义存 `pending_spec`，旧定义保留供对比）；消失 → 停用并标记 `missing`。`POST /api/v1/orgs/:orgId/apps/:appId/refresh` 改走同一套比对；新增 `POST .../apps/:appId/tools/:name/review {action: "approve" | "reject"}`（`apps.manage`，错误码 `app.tool_not_found` / `app.tool_not_pending`），approve 采用新定义并启用、默认策略按新注解重新推导（管理员设定的策略保留，工具视图新增 `policySource` / `pending` / `missing` / `reviewedAt`），reject 停用并保留旧定义；待复核的工具不能经 PATCH 启用。审计 `app.tools_drifted`（只有计数）与 `app.tool_reviewed`。个人凭据型应用的后台检查依次试至多 3 个现任成员的个人凭据。迁移 `0015_tool_drift.sql`。
  SDK：`ConnectorOpenArgs` 新增可选 `onToolsChanged?: () => void`（会话中远端报告工具清单变了时调用，内核投递一次漂移检查，jobId `drift-<appId>-<分钟桶>`）。connector-mcp：收到 `notifications/tools/list_changed` 时调用它。测试工具：`startFakeMcpServer` 新增 `sseResponses`，工具处理函数第二个参数 `ctx.notifyToolsChanged()`。
- 新增工具注册与 `connector@1` 契约：插件在 `setup` 期间用 `ctx.tools.register(spec, handler)` 注册工具（名称 `^[a-zA-Z0-9_-]{1,40}$`、描述非空、不可重复，`setup` 之后注册抛错）；SDK 导出 `ToolSpec` / `ToolResult` / `InputRequired` / `ToolError`、`Connector` / `ConnectorSession` 契约，以及纯函数 `validateToolSpec` / `validateInputForm` / `validateAnswer`（表单字段复用 `ParamSchema` 子集，新增导出 `checkParamValue`）。`connector` 登记为多选能力。
  `ModelRequest` 新增可选 `toolChoice: "auto" | "none"`（`model-provider@2`；`ModelRequestV1` 不含，内核的 `@1` 适配层不传）；`ToolError` 新增可选第二个参数 `{ kind?: "error" | "unavailable" }`（缺省 `error`，`unavailable` 表示远端不可用、计入应用熔断），原有用法不变；`validateAnswer` 只认答案自身的键（`Object.hasOwn`），并拒绝多选字段里的重复项。
