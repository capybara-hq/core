应用包（app.yaml）企业导入（C31，`AppImport`，`Kernel.apps`）：迁移 `0036_app_import_staging.sql`。`POST /api/v1/admin/directory/apps/prepare/file`（octet-stream，上限 `packages.maxBytes`，读请求体前认证企业管理员）与 `/apps/prepare/npm {package, version?}` → `{ stagingId, review }`：解析 app.yaml，按 lock 从 npm registry 拉取每个插件并按 sha512 校验（不符 502 `app.lock_mismatch`），校验图标、技能目录与连接器模板，内置 / 配置声明的插件不满足范围 409 `app.plugin_conflict`；全部通过后才入库插件包、把 app.yaml / 图标 / 技能写进对象存储、暂存 24 小时。审阅一次列出全部插件的权限、敏感项、迁移警告与 action（install / upgrade / keep）。`POST …/apps/:stagingId/confirm {reviewHash, deployPlugins}`：摘要不符或部署上的插件已变 409 `app.review_stale`，暂存不存在 / 过期 404 `app.staging_not_found`；一个事务里为要装的插件写快照（source web，审计 `plugin.permissions_approved` 带 `app`），建 kind app 的目录版本（`resolved = { plugins: [{ name, sha256 }] }`）；`deployPlugins` 时装到部署并启用（不重启）。清单引入 kind app 返回 200 `{ stagingId, review, permissionsMismatch }`。维护任务 `app-staging-cleanup` 每小时删除过期暂存与其对象。目录版本详情新增 `resolved`。新错误码 `app.invalid_manifest`、`app.lock_mismatch`、`app.review_stale`、`app.staging_not_found`、`app.plugin_conflict`。新配置 `directory.maxBundleBytes`（一次应用包导入的总字节，缺省 4 × `packages.maxBytes`，超出 413 `app.bundle_too_large`）。prepare 审计 `directory.app_staged`；降级到有未执行迁移的版本在 prepare / confirm 写之前 409 `plugin.downgrade_unsupported`。confirm 返回 `{ item, deploy }`：`deployPlugins` 时逐个给出 enabled / failed（+ code），部署失败不抛错，upgrade 没装上的恢复原快照（审计 `plugin.permissions_restored`）。
