Tool presentation for the conversation page: `GET /conversations/:id/tools?keys=…` returns each tool's title, kind (command, read, edit, search, connector, meta, tool), key arguments and source. `title` and `keyArgs` are left out of the tool definition fingerprint, so they never trigger drift review; a connector refresh that changes only them updates the stored definition silently and logs `connector.tool_display_updated`. Remote titles are cleaned of control, bidi and invisible characters (ZWNJ and ZWJ are kept) before they are kept. Builtin tools declare their key arguments.

An extension written without the SDK types that already passed a top-level `title` on a tool gets a new fingerprint for that tool: its remembered grants no longer match and older eval cases report the tool definition as changed.

A NUL byte in a tool result (a file read, command output) no longer fails the run: the event log stores every NUL in a payload as U+FFFD, since PostgreSQL jsonb rejects `\u0000`. Approval denials can carry a reason the model sees ("An approver denied this tool call. Reason: …"), and `approval_requested.policy` names the rule that asked (`role`, `agent`, `connector`, `fixed`, `org` or `default`).

Conversations are created on first send: `POST /conversations` takes an optional `message` (with a required `clientMessageId`) and writes the conversation and its first message in one transaction; a retry with the same `clientMessageId` returns the same conversation and event (200 instead of 201), and the same id with another agent is 409 `conflict`. `PATCH /conversations/:id` renames (1–120 characters, counted in code points, no control or format characters except ZWNJ and ZWJ) and stops title generation; `ConversationView` gains `titleSource`. Titles are generated by a model after the first completed run through the queue `cap-kernel-titles` and the new kernel model purpose `title` (unmapped → the conversation's current chat model), at most 3 attempts; the call's tokens are a `usage` event with `purpose: "title"` (no run), reported through `usage.report` (an estimate when the call failed after sending). The title model sees only the first message's typed text and the first reply, never `@` resource bodies. Title calls fire the `model.request` and `model.response` hooks with `purpose: "title"`; a policy denial skips the title for good (no retry) and writes one `hook.denied` audit row. The conversation stream sends `event: changed` with `{ "what": "title" }` when the title changes.

Model and effort can be switched mid-conversation: `POST …/messages` and the first message of `POST /conversations` take `model` and `effort`; a change is logged as a `model_switched` event before the message and applies from the next run that starts (`ConversationView.selection`, `event: changed` with `selection`). An unknown model is 400 `agent.model_unavailable`, an effort the model does not declare 400 `validation_failed`. A switched-to model that disappears falls back to the agent's model with a `model_switched` notice (`reason: "unavailable"`). Step and full-run replays use the switched model; a candidate model that replaces it reports the new drift reason `model_switched`.

Queued messages: `GET|POST /conversations/:id/queue`, `PATCH|DELETE …/queue/:itemId`, `POST …/queue/:itemId/send` and `POST …/queue/resume` (owner only). A queued message is kept in PG (`conversation_queue`, at most 20 per conversation, 409 `conversation.queue_full`) and is not in the event log until it is sent: after each run ends the head item goes out as its own `user_message`, one per run, never ahead of an unconsumed message; a run that fails or is stopped pauses the queue until `resume`; "send now" posts an item as an interjection. `@` resources are read with the sender's credentials when the message is queued (a full queue answers 409 before reading them). A queued message goes out only while its author can still use the conversation (active, a member, the agent visible to them); otherwise the queue pauses. Removing a member deletes their queued messages. Every change sends `event: changed` with `{ "what": "queue" }`.

File outputs: `GET /conversations/:id/files?after=&limit=` lists the files the agent delivered, newest first by first delivery (a new version keeps the file's place, so the cursor is stable), grouped by source path into versions (`version`, `versions` newest first, at most 20), with `status: "removed"` when the stored object is gone and `previewable: "image" | "text" | null`. `GET …/files/:fileId/content?limit=` returns the first bytes (at most 1 MiB) of a text file version, with `X-Content-Truncated: true` when cut; every type is served as `text/plain; charset=utf-8` with the stored type in `X-Content-Original-Type`, the response is sandboxed and never sniffed; a removed object is 410 `conversation.artifact_removed`. Delivering a file sends `event: changed` with `{ "what": "files" }`.

File previewers (`file-preview@1`): `GET /conversations/:id/files/:fileId/previewers` lists the extension previewers that take a file in the org's order, `GET …/files/:fileId/previews/:plugin/:previewerId` renders a view previewer (10 s → 504 `ui.timeout`, a throw → 502 `ui.render_failed`, an invalid view → 502 `ui.invalid_view`), and the embed-token route takes `fileId` for a `file-preview` embed (the token is for that one file and conversation). Admins order and disable previewers with `GET|PUT /orgs/:orgId/file-previewers` (`capybara.file_previewers`).

Extension UI places: `GET /orgs/:orgId/ui/contributions` lists the new places `panel`, `section` and `inline` with an `icon` (default `puzzle`); a contribution declared with the old `place: "conversation"` is listed as `place: "panel"` with `legacyPlace: "conversation"`, aliases (`aliasOf`) and `file-preview` embeds are not listed. Section and inline views follow the conversation access rule. `GET …/ui/views/:plugin/:id` takes `item` (passed as `args.item`) and `callId` / `key` (passed as `args.card`); fetching an alias renders the contribution it names. A plugin tool's `ToolResult.card` is recorded as `tool_result.card: { plugin, view, key? }` when it names an inline view of that extension, otherwise dropped with a warning; it is never part of a model request or compaction.

A retry after a failed run can say which message it repeats: `POST …/messages` takes `retryOf` (the seq of that message), recorded on the `user_message` for display only (the web folds it into the failed run's divider).

A denied approval's IM card shows the reason the person gave (redacted like the input), also for a sub-agent's approval once its card is brought up to date.
