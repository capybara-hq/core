Tool presentation for the conversation page: `GET /conversations/:id/tools?keys=…` returns each tool's title, kind (command, read, edit, search, connector, meta, tool), key arguments and source. `title` and `keyArgs` are left out of the tool definition fingerprint, so they never trigger drift review; a connector refresh that changes only them updates the stored definition silently and logs `connector.tool_display_updated`. Remote titles are cleaned of control, bidi and invisible characters before they are kept. Builtin tools declare their key arguments.

An extension written without the SDK types that already passed a top-level `title` on a tool gets a new fingerprint for that tool: its remembered grants no longer match and older eval cases report the tool definition as changed.

A NUL byte in a tool result (a file read, command output) no longer fails the run: the event log stores every NUL in a payload as U+FFFD, since PostgreSQL jsonb rejects `\u0000`. Approval denials can carry a reason the model sees ("An approver denied this tool call. Reason: …"), and `approval_requested.policy` names the rule that asked (`role`, `agent`, `connector`, `fixed`, `org` or `default`).

Conversations are created on first send: `POST /conversations` takes an optional `message` (with a required `clientMessageId`) and writes the conversation and its first message in one transaction; a retry with the same `clientMessageId` returns the same conversation and event (200 instead of 201). `PATCH /conversations/:id` renames (1–120 characters) and stops title generation; `ConversationView` gains `titleSource`. Titles are generated by a model after the first completed run through the queue `cap-kernel-titles` and the new kernel model purpose `title` (unmapped → the conversation's current chat model), at most 3 attempts; the call's tokens are a `usage` event with `purpose: "title"` (no run), reported through `usage.report`. The conversation stream sends `event: changed` with `{ "what": "title" }` when the title changes.

Model and effort can be switched mid-conversation: `POST …/messages` and the first message of `POST /conversations` take `model` and `effort`; a change is logged as a `model_switched` event before the message and applies from the next run that starts (`ConversationView.selection`, `event: changed` with `selection`). An unknown model is 400 `agent.model_unavailable`, an effort the model does not declare 400 `validation_failed`. A switched-to model that disappears falls back to the agent's model with a `model_switched` notice (`reason: "unavailable"`). Step and full-run replays use the switched model; a candidate model that replaces it reports the new drift reason `model_switched`.
