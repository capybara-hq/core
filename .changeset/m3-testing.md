- 应用 OAuth 认证：认证方式新增 `oauth_code`（个人凭据；MCP OAuth 发现 RFC 9728 → RFC 8414 或手填端点；RFC 7591 动态注册或手填 client，不支持 DCR 时 `app.connect_failed` 带 `dcr_unsupported`）与 `oauth_client`（组织凭据，客户端凭据流，token 缓存于凭据存储）。新增 `POST /api/v1/orgs/:orgId/apps/:appId/connect`（授权码 + PKCE S256，state 存 Redis 10 分钟、单次有效，回调须来自发起连接的浏览器）与公开路由 `GET /api/v1/oauth/callback`；access token 过期前 60 秒或收到 401 时在 `capk:oauth-refresh:*` 锁内刷新（不并发刷新），refresh 被拒 → 凭据删除并触发「需要连接」。OAuth 应用要求配置 `http.publicUrl`，可选 `tokenAuthMethod`；只有 `invalid_grant` / `invalid_client` / `unauthorized_client` 才作废令牌；`PUT .../credentials/org` 可轮换 OAuth 客户端；回调核对 RFC 9207 `iss`；新增配置 `tools.oauthAllowInsecureLoopback`（仅开发 / 测试）。测试工具：新增 `startFakeOAuthServer`，`startFakeMcpServer` 支持 `verifyBearer` 与 `protectedResource`（受保护资源元数据）。
- 工具定义漂移检测与复核（spec 7.3）：维护队列每 `tools.driftIntervalHours` 小时（job scheduler `drift-scan-interval`，多副本只有一个）对活动应用重新 listTools，与快照比对——新增工具 `pending_review`；定义变化 → `pending_review`（新定义存 `pending_spec`，旧定义保留供对比）；消失 → 停用并标记 `missing`。`POST /api/v1/orgs/:orgId/apps/:appId/refresh` 改走同一套比对；新增 `POST .../apps/:appId/tools/:name/review {action: "approve" | "reject"}`（`apps.manage`，错误码 `app.tool_not_found` / `app.tool_not_pending`），approve 采用新定义并启用、默认策略按新注解重新推导（管理员设定的策略保留，工具视图新增 `policySource` / `pending` / `missing` / `reviewedAt`），reject 停用并保留旧定义；待复核的工具不能经 PATCH 启用。审计 `app.tools_drifted`（只有计数）与 `app.tool_reviewed`。个人凭据型应用的后台检查依次试至多 3 个现任成员的个人凭据。迁移 `0015_tool_drift.sql`。
  SDK：`ConnectorOpenArgs` 新增可选 `onToolsChanged?: () => void`（会话中远端报告工具清单变了时调用，内核投递一次漂移检查，jobId `drift-<appId>-<分钟桶>`）。connector-mcp：收到 `notifications/tools/list_changed` 时调用它。测试工具：`startFakeMcpServer` 新增 `sseResponses`，工具处理函数第二个参数 `ctx.notifyToolsChanged()`。
- `startFakeMcpServer` 新增 `sessions`（有状态 Streamable HTTP 会话，服务端发起的请求的答复能送回原调用）、`prompts`（`FakeMcpPrompt`：参数与可自定义渲染）；工具处理函数的上下文新增 `elicit(params)`（表单 / URL 模式的 `elicitation/create`，记录在 `FakeMcpServer.elicitations`）；`FakeMcpRpcError` 可带 JSON-RPC `data`（如 `-32042` 的 `elicitations`）。
- 测试工具新增 `startFakeMcpServer({ tools, resources?, requireBearer?, unauthorizedTimes?, onCall?, intercept? })`（SDK 服务端、无状态 Streamable HTTP、127.0.0.1 随机端口；可模拟慢、报错、回显请求头、超大输出、401）与 `FakeMcpRpcError`。
- 测试工具新增 `startFakeOpenApiServer({ apiKey?, apiKeyIn?, echoKey?, specRedirect?, spec? })`（127.0.0.1 随机端口：`/openapi.json` 给出文档或 302，`/v1/*` 实现宠物 CRUD、回显、纯文本、二进制、500 与 302 操作，可要求 header / query 里的 API key，错误正文可回显收到的 key；`requests` 记录每个请求，`setSpec` 运行中替换文档）与默认文档 `defaultFakeOpenApiSpec(base, apiKeyIn?)`。
