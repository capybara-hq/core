- 调用按已复核的定义路由（Ruling A21）：`ToolSpec` 新增可选的不透明字段 `connectorData`（仅连接器工具），内核把它存进快照（`app_tools` / `tool_specs`）并计入 spec_hash，但从不发给模型；`ConnectorSession.callTool` 新增可选第 4 个参数 `ctx: { spec }`，内核传该工具已复核的定义（`app_tools.spec`，绝不是待复核的新定义）。connector-openapi 在 listTools 时把方法、路径模板、参数位置与风格、请求体媒体类型、解析好的服务器地址写进 `connectorData`，调用只按 `ctx.spec.connectorData` 构造请求、不再读取文档（缺失时提示管理员刷新应用）——远端文档改了方法 / 路径会改变指纹、进入漂移复核，复核通过前仍走旧路由；文档只在 listTools / inspect 时读取。
  应用列表与详情的 `endpoint` 不再回显 `text` / `*Text` 字段全文（如 OpenAPI 的 `specText`），换成 `<field>Bytes` 与 `<field>Sha256`（所有人一致；要改文档时重新上传）。
- 新增应用预览 `POST /api/v1/orgs/:orgId/apps/preview`（`apps.manage`，仅用户主体）：请求体同安装（`connector`、`endpoint`，可选 `auth` / `credential` / `name` / `slug`），什么都不写——用连接器的 `inspect`（有则）返回 `authHints` 与 `operations`，给了 `auth: none`、静态认证带凭据或客户端凭据流带 client 时再列工具，返回 `tools`（key、描述、inputSchema、注解、推导的默认策略、`issue`）与 `issues`；否则 `tools: null`（OAuth 授权码流不列，避免动态注册）。外连失败 502 `app.connect_failed`。
  安装 / 刷新 / 预览列工具失败时，连接器抛出的 `ToolError` 消息（按本次注入的凭据打码、截到 500 字符）会带进 `app.connect_failed` 的说明（如「Swagger 2.0 documents are not supported…」），其他错误仍只给错误类名。端点的凭据检查与对非管理员的隐藏从 `url` 扩展到所有顶层 `*Url` 字段（如 `specUrl`、`baseUrl`）。安装与预览两个路由的请求体上限放宽到 6 MiB（可携带 2 MB 的 OpenAPI 文档），其余路由不变。
- MCP elicitation、prompts 斜杠命令与 `@` 资源引用（D4）：
  - **elicitation**：应用工具调用途中远端发起 elicitation 时，内核把它映射成通用输入请求（表单模式按 InputForm 子集映射 `requestedSchema`；URL 模式为带 `url` 的表单与必填的「已完成」开关），**中止本次调用**并让运行等待（`question_asked`，表单经本次注入的凭据打码）；用户回答后照常用同一 input 重新发起调用，远端再次发起同样的 elicitation（表单按 `requestedSchema` + 文案、URL 按 origin + path + 文案匹配）时立即用答案答复（超时 / 取消 → `cancel`，URL 未勾选 → `decline`）。超出子集的表单立即 `decline` 并在工具结果后附英文说明；resources 工具一律拒绝。事件 `question_asked.form` 新增可选 `url`。
  - **prompts**：`GET /api/v1/orgs/:orgId/apps/prompts`（`apps.use`）列出当前用户可用应用的提示模板（缺个人凭据 / 连接失败的应用列在 `unavailable`）；`POST /api/v1/orgs/:orgId/apps/:appId/prompts/:name {arguments}` 以当前用户的凭据渲染为文本（打码、≤ 100000 字符）。
  - **resources**：`GET /api/v1/orgs/:orgId/apps/resources?query=` 按名称 / URI / 描述子串搜索（只列 `read_resource` 工具已启用的应用）；`POST .../conversations/:id/messages` 新增 `attachments: [{ appId, uri }]`（≤ 5），内核以发送者的凭据并行读取（打码、每个 ≤ 50000 字符、总时限 min(tools.timeoutMs, 30s)；该应用的 `read_resource` 工具被停用 → 409 新错误码 `app.resources_disabled`）作为用户文本之后的文本块写入同一条 `user_message`，并在 `payload.attachments` 记录元数据。
- 应用 OAuth 认证：认证方式新增 `oauth_code`（个人凭据；MCP OAuth 发现 RFC 9728 → RFC 8414 或手填端点；RFC 7591 动态注册或手填 client，不支持 DCR 时 `app.connect_failed` 带 `dcr_unsupported`）与 `oauth_client`（组织凭据，客户端凭据流，token 缓存于凭据存储）。新增 `POST /api/v1/orgs/:orgId/apps/:appId/connect`（授权码 + PKCE S256，state 存 Redis 10 分钟、单次有效，回调须来自发起连接的浏览器）与公开路由 `GET /api/v1/oauth/callback`；access token 过期前 60 秒或收到 401 时在 `capk:oauth-refresh:*` 锁内刷新（不并发刷新），refresh 被拒 → 凭据删除并触发「需要连接」。OAuth 应用要求配置 `http.publicUrl`，可选 `tokenAuthMethod`；只有 `invalid_grant` / `invalid_client` / `unauthorized_client` 才作废令牌；`PUT .../credentials/org` 可轮换 OAuth 客户端；回调核对 RFC 9207 `iss`；新增配置 `tools.oauthAllowInsecureLoopback`（仅开发 / 测试）。测试工具：新增 `startFakeOAuthServer`，`startFakeMcpServer` 支持 `verifyBearer` 与 `protectedResource`（受保护资源元数据）。
