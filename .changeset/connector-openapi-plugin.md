新增 OpenAPI 连接器插件 `@capybara-hq/plugin-connector-openapi`（`connector@1`，kind `openapi`）：端点 `{ specUrl? | specText?（二选一，JSON 或 YAML，≤ 2 MB）, baseUrl?（覆盖 servers）, operations?（勾选的 operationId，缺省 = 全部） }`，URL 须为 https，部署配置 `allowInsecureLoopback`（默认 false）打开时才允许确切的本机 http；只支持 OpenAPI 3.0 / 3.1（Swagger 2.0 给出明确错误），只展开内部 `$ref`（外部引用报错、绝不去取，循环引用换成宽松模式），3.0 的 `nullable` / 布尔 exclusive 边界转成 JSON Schema。每个 operation 一个工具：名 = operationId（非法字符换下划线、截到 40 字符；缺失时由方法与路径生成），描述 = summary + description（截到 1024 字符并注明）+ 方法与路径，inputSchema = `{ path?, query?, headers?, body? }` 中实际存在的部分（非 JSON 请求体为字符串），GET / HEAD 标 `readOnlyHint`、DELETE 标 `destructiveHint`。调用按 servers（变量取默认值）/ baseUrl 拼 URL，路径参数编码（拒绝 `.` / `..`），query 支持 form / explode / spaceDelimited / pipeDelimited / deepObject，工具参数不能设置 Authorization / Cookie 等头与未声明的头；每次请求前注入 `auth()`，401 → `onUnauthorized()` 后重试一次；不跟随重定向；文档不带凭据去取（限时 30 秒、限 2 MB），响应正文最多读 5 MB。结果给出状态、content-type 与正文（JSON 美化、文本原样、二进制给类型与大小），非 2xx → `isError` 附正文，5xx / 连不上 / 超时 → `ToolError`（`unavailable`）。实现可选的 `inspect`：`securitySchemes` → 认证提示（apiKey header / query、http bearer / basic、oauth2 clientCredentials / authorizationCode），以及操作清单。
